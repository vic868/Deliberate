# 05 · 技术转管理：角色转变与面试叙事

> 16 年 Java 经验不是"要放下的包袱"，而是**差异化竞争力** —— 关键在于把"我会写代码"翻译成"我能判断风险、定标准、带队伍"。

## 一、IC → Manager 的五个转变

| 维度 | 个人贡献者（IC） | 管理者（Manager） |
|---|---|---|
| 成功标准 | 我的产出又快又好 | **团队的产出**持续达标 |
| 工作对象 | 代码、系统 | **人 + 流程 + 目标** |
| 核心技能 | 技术深度 | 拆解、分工、沟通、决策、辅导 |
| 时间分配 | 自己动手 | 计划 20% / 沟通 40% / 辅导 20% / 干活 ≤20% |
| 风险态度 | 自己兜底 | **提前暴露**风险，带着方案上报 |
| 衡量单位 | 代码行/解决的 bug | 里程碑达成率、团队氛围、人才成长 |

**三句心法**：
1. 管理者的产出 = **团队产出 − 团队不在时的产出**（你的价值是杠杆，不是个人输出）。
2. 从"我能解决"变成"**我能让人解决，并让第二次更容易**"。
3. 不再追求"最强个人贡献者"，要追求"**让团队没有短板**"。

## 二、技术背景的"管理化翻译"（面试直接用）

| 你的技术资产 | 管理岗位话术 |
|---|---|
| 见过太多线上事故 | "建立了风险前置机制：把故障模式沉淀成检查清单，事故率下降 X%" |
| 16 年架构权衡经验 | "能在成本、性能、交付速度之间做**结构化决策**，而不是技术洁癖" |
| 带过新人/Code Review | "有**人才培养**经验：通过辅导+标准（DoD）把新人独立交付周期从 X 缩到 Y" |
| 跨系统联调协调 | "有**跨团队协作**经验：牵头过 N 方联调，用 RACI 消除责任灰色地带" |
| 推动过技术债治理 | "有**用业务语言争取资源**的经验：把技术债翻译成资损与人天，拿下排期" |
| PMP 系统学习 | "补齐了**项目管理方法论**：从凭经验到有基准、有变更控制、有复盘闭环" |

## 三、"为什么转管理"标准答案结构（PREP）

- **P 观点**：技术做到后面，瓶颈不再是个人能力，而是**协作与交付的确定性**。
- **R 理由**：我带的几个项目里，延期和事故的根因 80% 是需求澄清、排期机制、沟通断层 —— 这是管理问题不是技术问题。
- **E 例子**：XX 项目我用 WBS 重排 + 每日站会，联调阶段从 2 周压到 5 天；事故复盘用 5Why 沉淀了 3 条机制。
- **P 重申**：所以我想把 16 年的技术判断力和管理方法论结合，做能**对结果负责**的管理者。

## 四、面试高频问题清单（附答题思路）

| 问题 | 答题思路 |
|---|---|
| 你没做过管理，凭什么转？ | 事实承认 + 迁移证据：项目负责制/带新人/跨部门推动 → 3 个 STAR 案例 |
| 如何管比你资深的老员工？ | **不比技术比服务**：给资源、给授权、给认可，用 1on1 对齐诉求，让他成为 Tech Lead 代言人 |
| 团队不配合怎么办？ | 先找根因（目标不清/激励不足/流程卡点）→ 合作式冲突解决 → 必要时正式权力，但先穷尽非正式手段 |
| 任务完不成怎么办？ | 暴露 → 评估（关键路径/风险）→ 给出 A/B 方案（砍范围/加资源/调日期）→ 让上级决策，**不闷声扛** |
| 你怎么定优先级？ | 四象限 + 业务价值 + 依赖关系，讲清"放弃什么" |
| 如何做绩效/淘汰？ | 目标 SMART 提前对齐 + 过程 SBI 反馈留痕 + 结果公平透明 |
| 空降接手老团队？ | 前 30 天只听不动刀，找到"守门人"，快速赢一场小仗立信 |
| 你怎么带新人？ | 情境领导：新手用指令式 → 熟练后教练式 → 独立后授权式，配 DoD 和 1on1 |
| 如何保证质量不因赶工下滑？ | 质量基准 + 测试左移 + 代码评审标准，进度和质量冲突时上报做**范围取舍**而非砍测试 |
| 你的管理风格？ | "目标上对齐要严，过程上授权要足，反馈上直接但对事不对人" |

## 五、STAR 管理案例模板（写 3 个背熟）

```
【S 背景】项目/团队是什么规模、什么难点（人少、时间紧、跨 N 个团队…）
【T 任务】你个人要负责什么（用 RACI 说清你的 A）
【A 行动】3 个动作，每个挂一个模型：
   1. 用 WBS 拆解 / 用 5W1H 澄清需求 …
   2. 用 RACI + 里程碑分工盯盘 …
   3. 用 5Why 复盘沉淀机制 …
【R 结果】数字化：周期 -X%、事故 -X%、人效 +X%、按时交付 X/Y
```

## 六、上任 90 天计划（拿到 offer 后照着走）

| 阶段 | 主题 | 关键动作 |
|---|---|---|
| **0–30 天** | 只看不动，建立信任 | 1on1 每人一轮；搞清目标、账、人、坑；找到团队的"守门人"；**不动组织架构** |
| **31–60 天** | 小胜立信 | 挑一个**痛点小、见效快**的战役（如部署提速）打穿；建立会议节奏（站会/周会/1on1） |
| **61–90 天** | 立机制 | 上 WBS 排期 + RACI 分工 + 里程碑汇报；定 1 个季度 OKR；做第一次复盘并沉淀模板 |

> 90 天毕业标准：**目标对齐过、节奏跑起来、赢过一场小仗、至少培养出 1 个可托付的骨干**。
