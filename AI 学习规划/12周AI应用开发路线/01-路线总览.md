# 12 周路线总览

## 节奏建议

- 每周 6 天学习、1 天休息或轻量复盘；每天约 5 小时，按专注力切成 2–3 个学习块。
- 建议时间：概念学习 1 小时、编码实践 3 小时、记录与复盘 1 小时。项目周可把更多时间放在编码和调试。
- 每周至少留出一个可展示产物：代码、接口、评测报告、架构图或演示。
- 如果某周验收未通过，优先缩小范围并补齐核心链路，后续周次整体顺延。

## 阶段安排

| 周次 | 阶段 | 核心内容 | 周产出/验收 |
| --- | --- | --- | --- |

| 2 | 模型 API | API 调用、超时与重试、错误处理、流式输出、JSON 结构化结果 | 命令行 AI 助手：读取输入、调用模型、解析结果、处理异常 |

| 4 | Spring AI 工程能力 | 工具调用、流式响应、测试、配置隔离、服务封装 | 可演示的 AI 服务；测试正常、异常和流式路径 |

## 阶段门槛

### 第 1–2 周：AI 基础与 API

- [ ] 能说明 Token、Embedding、Attention、Transformer 和上下文窗口的关系。
- [ ] 能从命令行完成一次 API 调用，并覆盖超时、服务错误、非法响应和流式输出。
- [ ] 将密钥放在环境变量或本地忽略文件中，不写入仓库。

### 第 3–4 周：Spring AI 服务

- [ ] REST API 不把所有逻辑堆在 Controller 中；至少拆分配置、服务和 API 层。
- [ ] 有输入校验、统一错误响应、可关联请求的日志。
- [ ] 能展示结构化输出、记忆、工具调用和流式响应中的至少一条端到端路径。

### 第 5–8 周：完整 RAG

- [ ] 文档从上传到可检索、可更新、可删除，状态可追踪。
- [ ] 回答提供来源；权限在检索阶段执行，不能只依赖 Prompt。
- [ ] 使用固定问题集测量检索和回答效果，并能区分检索错误与生成错误。

### 第 9–10 周：受控 Agent

- [ ] 工具输入经过类型、范围和权限校验；关键写操作有人类确认。
- [ ] 能处理中断、重复请求、工具超时和部分失败。
- [ ] 对工具调用记录审计信息，不让模型自行扩大权限。

### 第 11–12 周：工程化与表达

- [ ] 新环境按文档可启动；配置和密钥不依赖个人机器状态。
- [ ] 能说明效果、延迟、成本、安全和可用性之间的取舍。
- [ ] 面试叙事区分已完成事实、测量结果和下一步设想，不虚构指标或就业结果。

## 每周复盘

每周末在 [[02-学习看板]] 记录：计划完成率、可运行产物、最重要的一个问题、下周需要调整的范围。每日记录使用 [[06-每日学习模板]]。
