# AI 应用工程化与交付

## 测试分层

- 单元测试：输入校验、切分、权限规则、错误映射和工具参数。
- 契约测试：模型/向量库适配器的请求与响应映射。
- 集成测试：摄取、检索、引用和 API 的端到端流程。
- 评测回归：固定问题集和固定配置，比较质量变化；记录模型和提示版本。
- 负向测试：超时、限流、非法 JSON、空检索、越权、客户端断连、重复提交。

对非确定性模型输出，测试稳定的结构、边界和关键事实，不应把易波动的整段文案当成唯一断言。

## 可观测性

建议按请求关联以下事件：API 入口、检索、重排、模型调用和工具调用。记录请求 ID、版本、延迟、状态和错误类别；采集原文、Prompt 和工具参数前先评估敏感数据与保留策略。

关键指标可包括：成功率、分阶段延迟、超时和重试、检索命中、拒答率、工具失败率、成本估算。指标要能支持定位具体失败样本。

## 发布前检查

- [ ] 配置从环境或部署密钥管理注入。
- [ ] 健康检查、关闭过程和依赖不可用行为明确。
- [ ] Docker 镜像可构建，启动指令和持久化目录有说明。
- [ ] 超时、连接池、并发和限流经过基本验证。
- [ ] 日志脱敏；权限和审计链路可检查。
- [ ] 有回滚或关闭高风险功能的操作方法。

## 成本与性能记录

将每次请求拆成模型调用数、输入/输出 token、Embedding 次数、检索/Rerank 次数和基础设施消耗。明确价格来源、时间、币种和估算假设；实际费用以部署环境和供应方账单为准。

优化时先测基线，再观察缓存、模型选择、上下文长度、并发和重试各自的影响，避免只优化单次模型响应而损害整体质量。
