# 项目实践手册：企业知识库与业务助手

## 项目目标

用一个逐步演进的 Spring Boot 应用串起 12 周成果：先完成模型 API，再加入 RAG，最后加入受控的业务工具。项目范围以个人可在 12 周内完成、能在本地演示为准。

## 建议模块

```text
ai-assistant/
├── api/                 # REST 请求、响应、校验
├── application/         # 用例编排和业务边界
├── model/               # 模型客户端、Prompt 和结构化输出
├── knowledge/           # 文档、解析、切块、检索和引用
├── tools/               # 受控只读/写入工具及授权
├── observability/       # 请求关联、耗时、错误和审计
└── deployment/          # Docker、本地配置样例和运行说明
```

目录仅是起步参考，可以按实际代码结构调整；不要为了套目录而制造空模块。

## 纵向交付

### 第 1–2 周：CLI 模型助手

- 输入：命令行文本；输出：模型回答或可诊断错误。
- 覆盖：配置读取、超时、有限重试、流式响应、JSON 解析、异常退出码。
- 验收：断网/错误响应时给出明确错误；密钥不出现在代码和日志中。

### 第 3–4 周：Spring AI HTTP 服务

- 暴露聊天接口，校验请求大小、会话 ID 和必要字段。
- 将模型调用封装在服务层；统一异常响应，支持流式与非流式路径。
- 验收：可通过 HTTP 客户端演示；有正常、非法输入和模型失败示例。

### 第 5–8 周：知识库 RAG

- 文档上传、解析和分块；保留来源、页码/段落、文档版本等元数据。
- 支持索引、查询、更新和删除；检索时执行用户/租户权限过滤。
- 回答携带来源；检索无证据时按设计拒答或明确说明证据不足。
- 使用 [[05-RAG评测与复盘]] 固定评测集建立基线并记录变化。

### 第 9–10 周：业务工具助手

- 先实现只读工具，如查询订单状态或库存；工具只返回必要字段。
- 写操作采用“生成操作预览 → 展示参数 → 用户确认 → 执行 → 返回结果”。
- 记录调用者、工具名、参数摘要、授权决策、执行结果和关联请求 ID。
- 验收：未授权用户、参数越界、重复请求、工具超时和用户拒绝均有确定行为。

### 第 11–12 周：交付

- 添加可复现的启动说明、环境变量样例、容器配置、接口文档和架构图。
- 记录固定测试集的质量结果、代表性延迟和成本估算的假设。
- 准备 3–5 分钟演示：需求、架构、核心链路、失败处理、指标和下一步。

## 展示材料清单

- [ ] README：目标、前置条件、配置、启动、接口调用、常见问题。
- [ ] 一张架构图，覆盖上传、索引、检索、模型、工具及身份边界。
- [ ] API 样例和至少一个完整演示脚本。
- [ ] 评测集和结果；标注数据范围、模型版本、提示版本及日期。
- [ ] 失败演示：无权限、无相关资料、模型超时或工具失败。
- [ ] 面试叙事：需求、取舍、效果证据、一次问题排查和后续改进。
