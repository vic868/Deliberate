# Agent、工具与工作流安全

## 设计原则

- 先判断任务是否需要模型动态选择工具；固定步骤优先使用确定性工作流。
- 工具是应用代码提供的受限能力，不是模型获得任意系统权限。
- 用户身份和授权由可信应用上下文传入，不接受模型自行声明身份。
- 只向模型暴露完成任务所需的最小工具和字段。

## 工具契约

```text
工具名与用途
输入 Schema（类型、必填、范围、枚举）
执行前权限检查
只读或写入标记
超时与速率限制
幂等策略/幂等键
稳定错误类别
审计字段
```

## 有副作用操作

推荐拆成两阶段：

1. 生成操作预览，包括目标对象、规范化参数和影响范围。
2. 由用户确认预览内容；确认应绑定该次操作和参数摘要。
3. 应用再次校验用户权限、对象状态和参数，再执行操作。
4. 返回结果并写审计记录；失败时按业务规则重试、补偿或进入人工处理。

不要让模型生成确认标记来代替真实用户确认。重复提交应有幂等保护。

## 多步流程恢复

- 每一步记录输入摘要、状态、输出引用和错误类别。
- 设置步骤数、循环次数、总耗时和成本上限。
- 对外部工具调用处理超时、部分成功和不确定结果；不确定时先查询状态，避免重复写入。
- 人工接管后保留可读的上下文和待处理事项。

## MCP 学习范围

先掌握 MCP 用来标准化模型应用与外部工具/上下文之间的交互，再用本地无敏感数据的最小例子观察客户端发现能力、调用工具和处理响应。对接具体实现时，应核对当前规范和 SDK 版本；MCP 本身不替代业务授权、参数验证、审计或确认流程。

## 验收案例

- [ ] 越权用户不能查询其他用户对象。
- [ ] 越界参数在工具执行前被拒绝。
- [ ] 用户拒绝确认后没有产生副作用。
- [ ] 相同写请求重试不会重复创建业务记录。
- [ ] 工具超时、部分成功和未知结果有可追踪处理路径。
