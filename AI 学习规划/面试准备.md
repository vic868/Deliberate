# 面试准备

> 目标岗位：AI 应用开发工程师 / AI 技术负责人。
> 分三块：硬技能题 / 系统设计题 / 领导力与软技能题。

## 一、硬技能高频题（都要能秒答）

### LLM 基础
- 什么是 Token？Context Window？如何管理长上下文？
- Temperature / Top-p 影响什么？什么场景调高调低？
- 什么是幻觉？有哪些缓解手段（引用溯源、拒答、知识库更新）？
- 预训练 / 微调 / Prompt 工程 / RAG 的区别与选择？

### Prompt 工程
- 什么是结构化 Prompt？有哪些要素？
- Few-shot / CoT / 角色扮演怎么用？什么时候失效？

### RAG
- RAG 为什么优于微调？两者怎么选？
- 完整 RAG 流程讲一遍（从文档到回答）
- 切分 chunk 的策略与参数怎么定？
- 检索不准怎么优化？（chunk、embedding、混合检索、Rerank、查询改写）
- 怎么评估 RAG？（召回率 / 准确率 / 引用正确率 / RAGAS）
- 权限怎么做到文档级隔离？

### Agent
- Agent 是什么？和普通对话/工作流的区别？
- 讲讲 ReAct、Plan-and-Execute
- 多 Agent 协作的架构怎么设计？
- Agent 常见的失败模式？怎么防止死循环？
- Function/Tool Calling 怎么设计？工具参数校验？
- MCP 是什么？解决什么问题？

### 工程与部署
- 流式输出怎么实现（SSE/WebSocket）？为什么不用普通 HTTP？
- 模型延迟高怎么办？降级 / 兜底方案？
- 成本怎么控制？（模型分层、缓存、压缩）
- 怎么观测一个 AI 系统？（Trace、Token、成本、评估）
- Prompt 注入是什么？怎么防护？

## 二、系统设计题（面试重头戏，白板讲）

### 常考题
1. 设计一个**企业知识库问答系统**（RAG）
2. 设计一个**智能客服系统**（Agent + 人工兜底）
3. 设计一个** AI 数据分析助手**（Text-to-SQL）
4. 设计一个** Agent 平台**（多 Agent、工具市场、可观测）

### 万能答题框架
```
① 需求澄清 → ② 场景/用户 → ③ 功能拆分 → ④ 技术选型（模型/向量库/框架）
→ ⑤ 系统架构图 → ⑥ 核心模块细节 → ⑦ 数据流 → ⑧ 评估指标
→ ⑨ 成本与风险 → ⑩ 扩展与演进
```

### 必讲细节
- 模型选型理由（效果 / 成本 / 延迟 / 合规）
- 向量库选型理由（数据量 / QPS / 运维成本）
- 缓存与降级：主模型挂了我怎么办
- 安全：权限、脱敏、审核
- 成本估算：给一个量级（如日活 1 万，月 Token 成本大概多少）

## 三、领导力与软技能题（总监定位必考）

- 让你从 0 带一个 AI 团队，怎么搭？（角色分工、招聘优先级）
- 业务方要一个"AI 需求"，你第一步做什么？（需求澄清、可行性验证、POC）
- 技术选型冲突，你怎么决策？（自研 vs 开源 vs API，摆事实列代价）
- 项目延期 / 模型效果不达标，怎么处理？（排期缓冲、降级方案、向上沟通）
- 你如何让 AI 项目产生业务价值？（先定指标、再谈技术）
- 你之前有管理经验吗？（没有就讲：如何组织学习小组、带新人、主导方案）

## 四、自我介绍模板（3 分钟）

```
我是 X，X 年 Java 后端开发经验。近 3 个月全职转型 AI 应用开发，
完成两个完整项目：
1. 企业知识库 RAG 系统（Spring AI + pgvector，混合检索 + 重排，检索命中率 93%）
2. 智能客服多 Agent（Function Calling + 人工审批，人工介入率下降 X%）
我熟悉 LLM 应用全链路：Prompt、RAG、Agent、可观测、成本与安全。
我的定位是能独立设计 AI 系统架构、能带团队落地的 AI 应用负责人。
```
