# 技术栈地图

> 面向"AI 应用开发负责人"的完整技能地图。
> 分为【必须精通】【必须会用】【了解加分】三层。

## 一、AI 基础（必须精通）

| 能力 | 掌握标准 |
| --- | --- |
| LLM 核心概念 | Token / Context / Temperature / 幻觉 / Embedding |
| Prompt 工程 | 结构化 Prompt、Few-shot、CoT、系统提示词 |
| API 工程 | 对话、流式、多轮、Function Calling、计费与上下文管理 |

## 二、Java 开发（必须精通 —— 你的底牌）

| 能力 | 掌握标准 |
| --- | --- |
| Spring Boot | 已有的：Restful、SSE、WebSocket、异步、线程池 |
| **Spring AI** | 对话、流式、Tool/Function、RAG、向量库集成 |
| **LangChain4j** | Agent、记忆、工具链、文档处理（作为互补） |

## 三、RAG 全链路（必须精通）

```
文档加载(PDF/MD/HTML) → 切分(chunking) → 向量化(Embedding) → 向量库
→ 混合检索(BM25+向量) → Rerank → Prompt 注入 → 模型回答 → 引用溯源
```

| 组件 | 常用选择 | 层级 |
| --- | --- | --- |
| Embedding | bge-m3、text-embedding-3-small | 必须会用 |
| Rerank | bge-reranker | 必须会用 |
| 向量库 | pgvector / Milvus / Chroma | 精通一种(pgvector) |
| 检索 | 向量 + BM25 混合、元数据过滤 | 必须精通 |
| 评估 | 自建测试集 + RAGAS | 必须会用 |

## 四、Agent（必须会用）

| 主题 | 掌握标准 |
| --- | --- |
| Agent 模式 | ReAct、Plan-and-Execute、Multi-Agent |
| 工具调用 | Tool / Function Calling 设计、错误处理 |
| 记忆 | 短期会话、长期向量记忆 |
| **MCP** | 理解协议，能用 MCP 接入工具 |
| Human-in-the-loop | 人工确认、审批流 |

## 五、企业级工程化（负责人必答）

| 维度 | 要点 |
| --- | --- |
| 可观测性 | Langfuse、OpenTelemetry、Trace/Token/成本 |
| 评估 | 离线测试集、线上 A/B、反馈回流 |
| 成本 | 模型分层、缓存、压缩、预算预警 |
| 稳定 | 降级兜底、超时重试、限流熔断、多模型切换 |
| 安全 | Prompt 注入防护、脱敏、内容审核、私有化 |
| 网关 | 统一接入多家模型、灰度发布 |

## 六、了解加分项（不用精通）

- 模型微调（LoRA/全参）：知道什么场景用、成本多少即可
- Python / LangChain：能读代码、能跑通 demo
- 多模态：语音（ASR/TTS）、视觉、视频
- 前沿方向：Agentic、Memory、World Model（看趋势，不深挖）
- 向量库调优：Milvus 集群、索引类型（HNSW）

## 七、软技能（总监/负责人必考）

| 能力 | 面试场景 |
| --- | --- |
| 系统设计 | 白板设计智能客服 / 知识库 / Agent 平台 |
| 技术选型 | 自研 vs 开源 vs API，给决策理由 |
| 团队管理 | 分工、排期、风险、如何培养下属 |
| 业务落地 | 讲清楚"这个 AI 功能给业务带来什么价值" |
