## 2026-10-06 追加：开机进 emergency mode ✅ 已修复

> 现象：每次开机停在 `You are in emergency mode... Give root password for maintenance`，要按 Ctrl-D 才能继续启动。

**根因**：`/etc/fstab` 挂载了一块**不存在的 NAS 盘**（外接 USB 盘），其中 `/dev/sdb1 /srv/nas` 一行没写 `nofail`：

```text
/dev/sdb1 /srv/nas ext4 defaults 0 2                          ← 无 nofail，盘不存在 → local-fs.target 失败 → emergency mode
UUID=4b5ff8cf-2643-444b-9209-239823f62f77 /mnt/nas ... nofail  ← 有 nofail 不阻塞，但每次开机白等 90 秒
```

- 机器只有一块 `sda`（Netac 240G SSD），`blkid` 全盘无 UUID `4b5ff8cf-...` → 盘不在机器上
- 开机同时报 `usb 2-2: device descriptor read/64, error -71` → 有个 USB 设备枚举失败，可能就是那块盘的硬盘盒接触不良
- 连锁影响：Samba 的 `[NAS]` / `[Public]` / `[NAS-Full]` 共享都指向 `/srv/nas`，盘不在共享一直是坏的

**处理（2026-10-06）**：
- [x] 备份原文件：`/etc/fstab.bak.20261006`、`/etc/environment.bak.20261006`
- [x] 注释掉 fstab 两行 NAS 挂载（注释里写了恢复方法），`systemctl daemon-reload` 后 `findmnt --verify` → 0 errors
- [x] `/etc/environment` 去掉无效的 `export` 前缀（该文件不是 shell，不支持 export 语法）
- [x] 停用 `nftables-load.service`（其规则文件第 207 行用了旧式 `xt CHECKSUM` 表达式，nft 原生不认，且 ufw 本来就是关闭的）

- [ ] **待办**：NAS 盘修好/插回后，把 fstab 里 UUID 那行取消注释（用 UUID 比 `/dev/sdb1` 内核名稳妥），Samba 共享随之恢复
- [ ] **待办**：排查 USB `error -71`——换线/换口/换硬盘盒试试，确认是否就是 NAS 盘
