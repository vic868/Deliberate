## P0 服务异常

- [ ] **修复 clash 容器崩溃循环**（已重启 3225 次）
	- 报错：`external-ui: /root/.config/clash/ui not exist`
	- 根因：挂载 `/opt/docker/clash/ui -> /opt/docker/clash/ui` 目标路径写错
	- 方案 A：删掉容器重建，挂载改为 `-v /opt/docker/clash/ui:/root/.config/clash/ui`
	- 方案 B：编辑 `/opt/docker/clash/config/config.yaml`，注释掉 `external-ui` 行，`docker restart clash`
	- 验证：`docker logs -f clash` 不再报 FTL，`docker ps` 状态为 Up

## P1 功能缺失

- [ ] **恢复 urban-renewal 的 API 后端（8080）**
	- 现象：`GET http://127.0.0.1:3000/api/` → 502，8080 无进程监听
	- 影响：3000 站点通过 frp 发布公网（subdomain `demos`），访客接口全挂
	- 待确认：8080 后端原来是什么服务、用什么方式启动的（`/opt/urban-renewal` 目录待排查）
	- 验证：`curl -o /dev/null -w "%{http_code}" http://127.0.0.1:3000/api/` 不再是 502

- [ ] **恢复 risk-controller 的 compose 文件**
	- 现象：`docker compose ls` 记录 `/opt/risk-controller/docker-compose.simple.yml` 与 `docker-compose.remote.yml`，目录已不存在
	- 做法：从运行容器反推
		```bash
		docker inspect risk-admin-backend risk-admin-frontend \
		  --format '{{.Name}} {{json .Config.Env}} {{json .HostConfig.PortBindings}} {{json .Mounts}}'
		```
	- 建议输出落到 `/opt/risk-controller/` 并用 `docker compose config` 校验

## P2 安全加固

- [ ] **启用 ufw 防火墙**（当前 inactive，全部端口对局域网开放）
	- 建议放行：22 / 80 / 3000 / 3001 / 5000 / 8000 / 7080（按实际需要收敛）
	- 数据库端口 3306 / 5432 / 6379 只对本机或指定 IP 放行

- [ ] **排查 vsftpd（21 端口）**
	- FTP 明文传输，确认 `local_enable` / 是否允许 root 登录（`/etc/ftpusers`）
	- 不用的话直接 `systemctl disable --now vsftpd`

- [ ] **确认 Samba（445/139）共享范围**
	- 检查 `/etc/samba/smb.conf` 是否有匿名可写共享
