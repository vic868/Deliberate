这段代码实现了一个经典的 **RAG（检索增强生成，Retrieval-Augmented Generation）** 问答流水线。它的核心目标是：**抓取指定网页的新闻内容作为私有知识库，当用户提问（“张成刚是谁？”）时，先从网页中检索相关段落，再让大模型基于检索到的事实进行回答，防止模型胡编乱造（防幻觉）**。

  

### 一、 整体执行流程

Plaintext

```
[网页 URL] ──► (1. 抓取与解析) ──► [原始 Document]
                                         │
[向量数据库 Chroma] ◄── (3. 向量化入库) ◄── (2. 文本切分 Chunks)
       │
  (4. 语义检索) ◄── 用户提问 ("张成刚是谁？")
       │
       ▼
[相关文档片段 Context] + [防幻觉提示词] + [用户问题]
       │
       ▼
  (5 & 6. 拼接并调用大模型) ──► 输出最终答案
```

### 二、 逐段代码详细拆解

#### 0. 初始化大模型与向量化模型

Python

```
client = get_lc_model_client()
llm_embeddings = DashScopeEmbeddings(
    model="text-embedding-v3", dashscope_api_key=os.getenv("DASHSCOPE_API_KEY")
)
```

- `client`：获取用于最终对话生成的大语言模型（LLM）实例。
    
      
    
- `llm_embeddings`：初始化阿里云灵积（DashScope）的 `text-embedding-v3` 向量模型。它的作用是**将人类阅读的文本转换为计算机能计算相似度的多维数字向量**。
    
      
    

#### 1. 加载与精准解析网页（Data Ingestion）

Python

```
loader = WebBaseLoader(
    web_path=["https://www.news.cn/fortune/20250212/895ac6738b7b477db8d7f36c315aae22/c.html"],
    bs_kwargs=dict(parse_only=bs4.SoupStrainer(class_=("main-left left", "title"))),
)
docs = loader.load()
```

- **作用**：爬取新华网这篇财经新闻的 HTML 内容，封装成 LangChain 的 `Document` 对象列表。
    
      
    
- **亮点（去噪）**：利用 BeautifulSoup 的 `SoupStrainer`，**只提取 CSS 类名为 `main-left left`（正文区）和 `title`（标题）的 HTML 标签**。这过滤掉了网页导航栏、广告、页脚等无关噪音，能大幅提升后续检索的准确率。
    
      
    

#### 2. 文本切分（Chunking）

Python

```
splitter = RecursiveCharacterTextSplitter(chunk_size=500, chunk_overlap=100)
documents = splitter.split_documents(docs)
```

- **作用**：大模型有上下文长度限制，且整篇文章一起检索颗粒度太粗。这里将长文章切分成多个小块（Chunks）。
    
      
    
- **参数解析**：
    
      
    - `chunk_size=500`：每个文本块最大约 500 个字符。
        
          
        
    - `chunk_overlap=100`：相邻两个文本块之间保留 100 个字符的重叠。**这样做的目的是防止一句话或一个完整语义在切分边界处被“拦腰截断”**。
        
          
        
    - `RecursiveCharacterTextSplitter`：递归字符切分器，会优先按段落（`\n\n`）、换行（`\n`）、句号等自然分隔符切分，尽量保持语义完整。
        
          
        

#### 3. 向量化与入库（Embedding & Vector Storage）

Python

```
vector_store = Chroma.from_documents(documents=documents, embedding=llm_embeddings)
```

- **作用**：遍历切分好的 `documents`，调用前面配置的 `text-embedding-v3` 把每段文字变成向量，并存入本地轻量级内存向量数据库 **Chroma** 中。
    
      
    

#### 4. 构建检索器（Retriever）

Python

```
retriever = vector_store.as_retriever()
```

- **作用**：将 Chroma 向量库包装成 LangChain 标准的检索器接口。默认情况下，当接收到一个问题时，它会计算问题向量与库中所有文本块向量的余弦相似度，并返回最相似的前 4 个片段（`k=4`）。
    
      
    

#### 5. 编写提示词模板与防幻觉约束（Prompt Engineering）

Python

```
system_prompt = """您是问答任务的助理。使用以下检索到的上下文来回答问题。
如果你不知道答案，就说你不知道。"""
prompt_template = ChatPromptTemplate.from_messages([
    ("system", system_prompt),
    ("assistant", "{context}"),
    ("human", "{input}"),
])
```

- **防幻觉约束**：明确告诉模型“不知道就说不知道”，强制模型只依据检索到的事实作答，而不是靠训练时的记忆去编造。
    
      
    
- **占位符**：`{context}` 用来动态填入检索器找出来的网页片段；`{input}` 用来填入用户的实际提问。
    
      
    

#### 6. 组装链条并执行（Chains & Invocation）

Python

```
chain1 = create_stuff_documents_chain(client, prompt_template)
chain2 = create_retrieval_chain(retriever, chain1)

resp = chain2.invoke({"input": "张成刚是谁？"})
print(resp["answer"])
```

这里使用了 LangChain 经典的**两级链条嵌套**：

  

1. **`chain1`（文档合并链 `create_stuff_documents_chain`）**：`Stuff` 的意思是“塞入”。它的工作是把检索出来的多个 `Document` 片段的文本拼接到一起，塞进 `prompt_template` 的 `{context}` 占位符中，然后发给大模型 `client` 生成答案。
    
      
    
2. **`chain2`（检索链 `create_retrieval_chain`）**：它把检索动作和生成动作串联起来。当调用 `chain2.invoke({"input": "张成刚是谁？"})` 时，内部会自动执行：
    
      
    - 把 `"张成刚是谁？"` 传给 `retriever` 检索出网页中提到张成刚的段落；
        
          
        
    - 将检索结果作为 `context`，连同原始 `input` 一起交给 `chain1`；
        
          
        
    - 最终返回一个字典 `resp`，其中 `resp["context"]` 是引用的原文片段，`resp["answer"]` 是大模型的最终回答。
