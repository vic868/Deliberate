```
┌─────────────────────────────────────────────────────┐
│  每次 invoke:  {"input": "你好", "language": "中文"} │

│                    ↓                                 │

└─────────────────────────────────────────────────────┘
```

## 🔍 逐段解析

### Prompt 设计（L8-12）
```python
prompt_template = ChatPromptTemplate.from_messages([
    ("system", "你是一个聊天助手，用{language} 回答所有的问题"),
    MessagesPlaceholder(variable_name="history"),
    ("human", "{input}"),
])
```

**三个变量各司其职：**

| 变量 | 类型 | 来源 | 作用 |
|---|---|---|---|
| `{language}` | 普通字符串 | 每次 invoke 传入的 dict 字段 | 控制回答语言 |
| `{history}` | 消息列表 | `RunnableWithMessageHistory` 自动注入 | 多轮记忆 |
| `{input}` | 普通字符串 | 每次 invoke 传入的 dict 字段 | 当前轮用户输入 |

**一个精妙之处**：`{language}` 不在 `RunnableWithMessageHistory` 的配置里（既不是 `input_messages_key` 也不是 `history_messages_key`），但它照样能透传到 prompt 里 — 因为 LangChain 会把 invoke 时传入 dict 的**所有字段**都喂给 prompt。

---

### 会话存储（L22-26）
```python
store = {}
def get_session(session: str):
    if session not in store:
        store[session] = ChatMessageHistory()
    return store[session]
```

这是 `RunnableWithMessageHistory` 的**核心回调**：
- 它不会自己管理存储，你通过 `get_session` 告诉它"给你一个 session_id，你去这里拿历史对象"
- 生产环境把 `store` 换成 **Redis** 或**数据库**即可（注释里也提到了）
- 同一个 `session_id` 多次调用 → 共享同一个历史对象 → 自动续记忆

### 包装成带记忆的链（L28-33）
```python
chatbot = RunnableWithMessageHistory(
    chain,                  # 基础链（无记忆的纯处理逻辑）
    get_session,            # session_id → 历史对象 的映射函数
    input_messages_key="input",     # invoke dict 里"当前输入"的 key
    history_messages_key="history", # prompt 里 MessagesPlaceholder 的 variable_name
)
```

**配置对应关系一定要对齐：**
```
invoke({"input": "你好", "language": "中文"})  →  ↑input_messages_key
                                                    │
prompt: ("human", "{input}")         ←─────────────┘

prompt: MessagesPlaceholder(variable_name="history")  ← history_messages_key
```

如果 `input_messages_key` 写成别的值（比如 `"message"`），那 invoke 时就要传 `{"message": "你好", ...}`，否则会报 key 找不到。

### 双会话隔离演示（L35-39）
```python
cfg_zh = {"configurable": {"session_id": "yunfang_chinese"}}
cfg_en = {"configurable": {"session_id": "yunfang_english"}}

chatbot.invoke({"input": "你好", "language": "中文"}, config=cfg_zh)
chatbot.invoke({"input": "你好", "language": "英文"}, config=cfg_en)
```

**执行后的 store 状态：**
```python
store = {
    "yunfang_chinese": ChatMessageHistory(messages=[
        UserMessage("你好"),
        AIMessage("你好！很高兴认识你~"),
    ]),
    "yunfang_english": ChatMessageHistory(messages=[
        UserMessage("你好"),
        AIMessage("Hello! Nice to meet you~"),   # 记住了"用英文"
    ]),
}
```

**这就是 session_id 隔离的威力**：同一个 chatbot 实例，用不同 `session_id` 调用 → 互不干扰，各自维护独立的记忆。这是手动 `ChatMessageHistory` 方式做不到的（手动方式要自己维护一个字典存 history 对象）。

### 流式调用（L43-45）
```python
for chunk in chatbot.stream({"input": "讲个笑话", "language": "中文"}, config=cfg_zh):
    print(chunk, end="", flush=True)
```

**和 invoke 的区别：**

| 方式 | 返回值 | 体验 |
|---|---|---|
| `invoke()` | 完整字符串（等 LLM 全生成完） | 等几秒出一坨 |
| `stream()` | 逐 token yield | 打字机效果，响应快 |

**注意**：`stream` 同样会自动管理历史 — 流式结束后，完整的 AI 回复会被自动回写到 `store["yunfang_chinese"]` 里。
