## 一、链路全景（五跳）

```text
① 生产          ② 流处理           ③ 落盘              ④ 挂载            ⑤ 加工
KafkaDataGenerator  Dinky → Flink     HDFS staging       ODS 外部表        DWD 内表
（本地 Mac）      （k3s session）   /data/staging/…     JsonSerDe        ORC + DECIMAL
   │                  │                 │                  │                │
   ▼                  ▼                 ▼                  ▼                ▼
Kafka topic      KafkaSource →     dt=…/hr=…/          ADD PARTITION     INSERT OVERWRITE
flink-demo       FileSink 滚动写    part-*.json         LOCATION 映射     去重+CAST+解析时间
   :9092             每 60s checkpoint 转正文件         元数据登记          幂等可重跑
```

| 跳 | 执行者 | 运行位置 | 本文档对应节 |
|---|---|---|---|
| ① 消息生产 | `KafkaDataGenerator`（Flink 1.14 本地 mini-cluster） | 你的 Mac | 二 |
| ② 消费 + 写 HDFS | Flink SQL 作业（`kafka_src` → `hdfs_ods`） | k3s Flink 1.20 session 集群，经 Dinky 提交 | 三 |
| ③ HDFS → ODS | `ALTER TABLE … ADD PARTITION` | HiveServer2（hive-server 容器） | 四 |
| ④ ODS → DWD | `INSERT OVERWRITE … SELECT`（Tez） | Hive on YARN | 五 |
| ⑤ 查询 | Hue / beeline | Hue(8888) / HS2(10000) | 六 |

## 三、第 2 跳：Flink 消费 + 写 HDFS

**提交入口**：Dinky（http://192.168.0.106:30888）任务 `flink-demo-di`，**执行模式 = Remote**（指向 session 集群 REST `http://192.168.0.106:30081`）。
**运行位置**：k3s Flink 1.20 session 集群（JM + 2×TM）。

**作业 SQL（三段）**：

```sql
SET execution.checkpointing.interval = 60s;   -- ★ 必须有：文件靠 checkpoint 转正

CREATE TABLE kafka_src ( ... ) WITH (
  'connector'='kafka', 'topic'='flink-demo',
  'properties.bootstrap.servers'='192.168.0.106:9092',
  'properties.group.id'='flink_hdfs_sink',
  'scan.startup.mode'='earliest-offset',
  'json.ignore-parse-errors'='true', 'format'='json');

CREATE TABLE hdfs_ods ( ... , dt STRING [, hr STRING] ) PARTITIONED BY (dt[, hr]) WITH (
  'connector'='filesystem',
  'path'='hdfs://192.168.0.106:8020/data/staging/flink-demo[-stream]',
  'format'='json',
  'sink.rolling-policy.rollover-interval'='15 min');

INSERT INTO hdfs_ods SELECT *, 分区表达式 AS dt[, … AS hr] FROM kafka_src;
```

**落盘产物**：`/data/staging/<根>/dt=YYYY-MM-DD[/hr=HH]/part-<uuid>-<n>.json`
- 写入中：`.part-…inprogress.<uuid>`（隐藏文件，Hive 不读）
- **checkpoint 完成后**才转正为可见的 `part-…` 文件——这是"数据可见性由 checkpoint 控制"的核心机制

**验证**：

```bash
curl -s http://localhost:30081/jobs                        # 作业 RUNNING
curl -s http://localhost:30081/jobs/<jobId>/checkpoints    # completed 数在增长
docker exec hadoop hdfs dfs -ls -R /data/staging/flink-demo-stream | grep -v inprogress
```

> 本跳踩过的坑（详见 [[Dinky修复方案]] / [[Flink-on-K8s-vs-YARN]]）：Dinky 变体错配、extends 空目录、缺 kafka 连接器、DN 注册 docker 内网 IP、UFW 拦截容器→宿主机、apply vs rollout restart。

## 四、第 3 跳：HDFS → ODS（外部表挂载）

**执行者**：Hive `ALTER TABLE … ADD PARTITION`（把 HDFS 目录登记进元数据）。

**原理**：ODS 是 `EXTERNAL TABLE` + `JsonSerDe` + `LOCATION`，分区目录 `dt=…/hr=…` 与表的分区列一一对应。**HDFS 有文件 ≠ Hive 能查**，必须 ADD PARTITION。

```sql
-- 挂某个分区（Flink 滚动落盘后执行）
ALTER TABLE ods.flink_demo_hi ADD IF NOT EXISTS PARTITION (dt='2026-10-07', hr='15');

-- 或按目录结构批量修复（分区多时慢，慎用）
MSCK REPAIR TABLE ods.flink_demo_hi;
```

**验证**：

```sql
SHOW PARTITIONS ods.flink_demo_hi;
SELECT COUNT(*) FROM ods.flink_demo_hi WHERE dt='2026-10-07';
```

**现状（本环境）**：
- 路径 A（宿主机脚本 `load_kafka.sh` 消费落盘）：`/data/staging/flink-demo`，dt 单级分区 → 表 `ods.flink_demo_di`
- 路径 B（Flink FileSink 直写）：`/data/staging/flink-demo-stream`，dt+hr 双级分区 → 表 `ods.flink_demo_hi`
- 两条路径并存、互为备份；生产选一条即可（推荐 B，实时性更好）

## 五、第 4 跳：ODS → DWD（加工层）

**执行者**：Hive + Tez（跑在 YARN 上，作业可在 8088 看到）。

**加工内容**：① 按 `orderId` 去重（ODS 允许重复，DWD 保证唯一）② 金额 `CAST` 成 `DECIMAL(12,2)` ③ 毫秒时间戳解析成 `TIMESTAMP` ④ 按分区 `INSERT OVERWRITE`（幂等重跑）。

```sql
INSERT OVERWRITE TABLE dwd.flink_demo_hi PARTITION (dt='2026-10-07', hr='15')
SELECT orderId, userId, product,
       CAST(amount AS DECIMAL(12,2)),      -- ★ 金额精度在 DWD 层收敛
       city, platform,
       FROM_UNIXTIME(CAST(`timestamp`/1000 AS BIGINT))
FROM (SELECT *, ROW_NUMBER() OVER (PARTITION BY orderId ORDER BY `timestamp` DESC) AS rn
      FROM ods.flink_demo_hi WHERE dt='2026-10-07' AND hr='15') t
WHERE rn = 1;
```

> `INSERT OVERWRITE` = 分区级覆盖 → 同一分区重跑任意次结果一致（幂等）；ODS 作为原始凭证永不被改写。

## 六、第 5 跳：查询消费

**Hue**（http://192.168.0.106:8888，admin / Hadoop@2026）或 beeline。

```sql
-- 城市 GMV（金额已是 DECIMAL，结果精确到分）
SELECT city, COUNT(1) AS orders, SUM(amount) AS gmv
FROM dwd.flink_demo_di
WHERE dt='2026-10-08'
GROUP BY city ORDER BY gmv DESC;

-- 平台分布
SELECT platform, COUNT(1), ROUND(AVG(amount),2) FROM dwd.flink_demo_di GROUP BY platform;
```

## 七、专题：amount 为什么 ODS 是 DOUBLE、要不要改

**结论：ODS 保持 DOUBLE 是正确设计，不用改；精度在 DWD 层收敛（本环境已生效）。**

| 层 | amount 类型 | 依据 |
|---|---|---|
| ODS（`ods.flink_demo_hi`） | `double` | **原样原则**：JSON 里 amount 本就是双精度数，ODS 忠实保存，便于回溯原始值 |
| DWD（`dwd.flink_demo_hi` / `dwd.flink_demo_di`） | **`decimal(12,2)`** ✅ 已实测确认 | **加工层收敛精度**：金额/对账字段一律 DECIMAL，聚合不再出现 `xxx.11999999994` |

**原理回忆**：DOUBLE 是二进制浮点，`358.2` 实际存成 `358.19999999…`；单条查询显示时被舍入掩盖，`SUM` 累加后误差暴露。DECIMAL 是十进制定点，精确。

**如果确实想让 ODS 也精确**（一般不需要）：
```sql
-- 方式一：查询时转（推荐，不动存储）
SELECT CAST(amount AS DECIMAL(12,2)) FROM ods.flink_demo_hi;
-- 方式二：重建 ODS 表为 DECIMAL（放弃"原样"特性，不推荐）
```
**禁止**：在 DOUBLE 列上直接 `SUM` 后拿去对账。

## 九、一键复现命令清单（按顺序）

```bash
# ① 生产消息（Mac）
cd /Users/vic/workspace-202606/ruoyi/flink && ./start.sh produce &

# ② 提交 Flink 作业（Dinky UI 或 sql-client）
#    Dinky: http://192.168.0.106:30888 → 任务 flink-demo-di → Remote 模式提交
#    sql-client: kubectl -n flink exec -it deploy/flink-jobmanager -- sql-client.sh

# ③ 等 checkpoint（60s）后检查落盘
kubectl -n flink exec deploy/flink-jobmanager -- true   # 确认可用
docker exec hadoop hdfs dfs -ls -R /data/staging/flink-demo-stream | grep -v inprogress

# ④ 挂 ODS 分区
docker exec -i hive-server beeline -u "jdbc:hive2://localhost:10000" -n hive --silent=true \
  -e "ALTER TABLE ods.flink_demo_hi ADD IF NOT EXISTS PARTITION (dt='2026-10-08', hr='10');"

# ⑤ ODS → DWD（幂等）
docker exec -i hive-server beeline -u "jdbc:hive2://localhost:10000" -n hive --silent=true \
  -e "INSERT OVERWRITE TABLE dwd.flink_demo_hi PARTITION (dt='2026-10-08', hr='10')
      SELECT orderId, userId, product, CAST(amount AS DECIMAL(12,2)), city, platform,
             FROM_UNIXTIME(CAST(\`timestamp\`/1000 AS BIGINT))
      FROM (SELECT *, ROW_NUMBER() OVER (PARTITION BY orderId ORDER BY \`timestamp\` DESC) rn
            FROM ods.flink_demo_hi WHERE dt='2026-10-08' AND hr='10') t WHERE rn=1;"

# ⑥ 查询（Hue 或 beeline）
docker exec -i hive-server beeline -u "jdbc:hive2://localhost:10000" -n hive --silent=true \
  -e "SELECT city, COUNT(1), SUM(amount) FROM dwd.flink_demo_hi GROUP BY city;"
```
