## 七、网络安全

> [!warning] Docker 发布端口绕过 UFW
> UFW 是 **active** 的（默认 deny incoming，放行 20/21/22/80/443/888/8888/10591/39000-40000/8001），但已实测 iptables 的 `DOCKER` 链对发布端口直接 ACCEPT——**上面列的所有 Docker 端口实际对局域网全开**，包括 ES 9200、Kafka 9092、Redis 6379、MySQL 3306、HBase 全家。要让 UFW 真正管住 Docker 端口，需要 `ufw-docker` 方案或把端口绑定 127.0.0.1。

其他：宝塔面板 10591 对外放行（有登录鉴权）；FTP 20/21 在放行列表里但这台机器没装 vsftpd（规则是宝塔默认套模板，可清理）。

## 八、发现的问题与建议

> [!warning] P1 — Milvus 三件套挂了 9 天 ✅ 已于 2026-10-06 恢复
> `milvus-standalone` 9-27 05:19 被 SIGKILL（当时 ExitCode 137，`OOMKilled=false`），etcd/minio 是 Exit 0 正常停止；栈停了 9 天后于 10-06 由用户手动拉起。**当前三件套全部 healthy，etcd 健康检查 FailingStreak=0，gRPC 19530 连通，collection 数据完好恢复中**。注意容器的 RestartPolicy=no，**重启机器后需要手动 `docker compose -f /opt/milvus/docker-compose.yml up -d`**。

> [!warning] P2 — k3s 里的 my-nginx 僵死部署
> 3 个副本 0/1 Unknown 已 18 天。不用就删：`k3s kubectl -n default delete deploy my-nginx`；要用就 `k3s kubectl -n default rollout restart deploy my-nginx`。

> [!note] P3 — 小项
> - `registry:2` 退出 2 个月：镜像都已本地化，只在需要 push/pull 时才要它，可不管或删容器
> - 宝塔面板纯属闲置（无站点、项目目录空壳），不用可考虑卸载减少攻击面
> - UFW 放行清单里的 20/21（FTP）是模板残留，可删

## 九、体检结论

- 失败单元 **0** · fstab 校验 **0 errors** · UFW **开启** · 容器除 Milvus 外全部健康
- 和 103 机（2C/11G 老笔记本）相比，这台才是正经的"大数据机"：6 核 + 48G + NVMe，跑 Flink/Kafka/ES/HBase 毫无压力，内存余量 31G
- 2026-10-06 Hadoop 评估（实测）：NVMe 读 1630 / 写 1100 MB/s；稳态 load 1.0~1.5、可用内存 29G；Hadoop 默认端口仅 9000（Portainer）冲突 → NN RPC 用 8020，其余 9870/8088/8030-33/19888 全空闲。**结论：部署 Hadoop 非常合适**，可与现有 Kafka/Flink/HBase/ES 串成完整数据链路（Kafka→Flink→HDFS、HBase on HDFS）；建议 YARN 6 vcores + 16G，replication=1；局限仍是单机伪分布式 + 137G 剩余磁盘
- 备查命令与 103 机相同（`docker ps -a`、`docker compose ls -a`、`ss -tlnp`、`systemctl --failed`、`findmnt --verify`），k3s 需用全路径 `/home/vic/.local/bin/k3s kubectl`
