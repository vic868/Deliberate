1. Feed 流架构演进（推拉结合模型）

写扩散（推模式，Push）： ^5FeOXAMB

适用场景：粉丝量少（如几百到几千）的普通用户。 ^gHyNLcxS

机制：发布微博后，通过异步任务将微博 ID 写入所有粉丝的收件箱（Timeline 缓存，通常是 Redis 的 ZSet 或 List）。 ^rXp4mnXK

优势：粉丝读取极其快速，直接读取自己的收件箱即可，读性能最高。 ^NjWAFIiM

3. 极致内存优化的独立计数系统（Counter Service） ^pzOBix8l

微博上每条微博都有“转发数、评论数、点赞数”，用户有“粉丝数、关注数、微博数”。这类数据读写极高且频繁变动，若直接放 MySQL 或标准 Redis Hash，内存开销和 IO 压力无法承受。 ^89cem5Me

紧凑内存排布：采用紧凑数组/位图结构，省去通用键值对中大量的指针和元信息开销，单台机器能够支撑百亿级别的计数量。 ^kSv7Jj3F
