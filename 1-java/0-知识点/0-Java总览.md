## 三、30 秒速查表

| 问题 | 一句话答案 | 详见 |
|---|---|---|
| `==` 和 `equals` | `==` 比引用/值，`equals` 默认也是 `==`，需重写才有语义；**重写 `equals` 必须重写 `hashCode`** | [[1-语言基础与面向对象]] |
| `Integer` 的 `==` 为什么有时相等 | `-128~127` 有缓存，超出范围是不同对象 | [[1-语言基础与面向对象]] |
| String 为什么不可变 | 常量池复用、线程安全、hash 可缓存；代价是每次修改都新建 | [[1-语言基础与面向对象]] |
| 抽象类 vs 接口 | 抽象类表达 **is-a** 且可有状态；接口表达**能力契约**，可多实现，支持 `default` | [[2-面向对象与设计模式]] |
| 重载 vs 重写 | 重载是**编译期静态分派**（按参数类型选），重写是**运行期动态分派**（按实际类型选） | [[1-语言基础与面向对象]] |
| 泛型为什么不能 `new T[]` | **类型擦除**：运行时 `T` 已是 `Object`/上界，无法确定数组元素类型 | [[3-泛型反射与注解]] |
| `HashMap` 为什么容量是 2 的幂 | 让 `(n-1) & hash` 等价取模，且扩容时只判断高位即可决定新位置 | [[1-集合框架]] |
| `HashMap` 为什么线程不安全 | 并发 put 丢数据；**1.7 头插在并发扩容下会成环导致 CPU 100%** | [[1-集合框架]] |
| `ArrayList` vs `LinkedList` | 绝大多数场景选 `ArrayList`：数组缓存友好，`LinkedList` 的"增删快"是有条件的 | [[1-集合框架]] |
| IO 多路复用为什么快 | 一个线程管多个连接；**epoll** 用红黑树+就绪链表，O(1) 拿到就绪事件 | [[3-IO与网络编程]] |
| 零拷贝是什么 | 数据不进用户态，`sendfile` 把 4 次拷贝降到 2 次（**Kafka/Netty 都靠它**） | [[3-IO与网络编程]] |
| `volatile` 保证什么 | 保证**可见性**与**有序性**（内存屏障），**不保证原子性** | [[4-多线程与内存模型]] |
| happens-before 是什么 | 判断"一个操作的结果对另一个是否可见"的规则集，**不等于时间先后** | [[4-多线程与内存模型]] |
| synchronized 锁升级 | 无锁 → 偏向锁 → 轻量级锁（CAS 自旋）→ 重量级锁（内核互斥量） | [[4-多线程与内存模型]] |
| ThreadLocal 会内存泄漏吗 | 会。**key 弱引用被回收、value 强引用滞留**，线程池下必须 `remove()` | [[4-多线程与内存模型]] |
| 线程池任务提交顺序 | **核心线程 → 入队 → 扩容到 max → 拒绝**；（反直觉的是"先入队再扩容"） | [[5-线程池]] |
| 为什么不用 `Executors` | 固定/单线程池用**无界队列**会堆积 OOM；缓存池 `max=MAX_VALUE` 会线程爆炸 | [[5-线程池]] |
| 线程数怎么定 | CPU 密集 ≈ 核数+1；IO 密集 ≈ 核数×(1+等待/计算)，**最终要靠压测** | [[5-线程池]] |
| AQS 的核心 | `volatile state` + **CLH 双向队列** + 模板方法；`ReentrantLock` 等都是它的子类 | [[6-JUC并发工具]] |
| `LongAdder` 为什么快 | 用 `Cell` 数组**分散 CAS 热点**，代价是 `sum()` 非强一致 | [[6-JUC并发工具]] |
| 三级缓存解决什么 | 循环依赖。第三级是为了**在被依赖时才决定是否生成 AOP 代理** | [[13-Spring源码骨架]] |
| 对象在哪分配 | 优先 **TLAB/Eden**，逃逸分析可栈上分配；大对象直接进老年代 | [[7-JVM内存与GC]] |
| 怎么判断对象可回收 | **可达性分析**（GC Roots），不是引用计数（解决不了循环引用） | [[7-JVM内存与GC]] |
| 常见 GC 收集器怎么选 | 低延迟看 **G1/ZGC**；吞吐优先看 Parallel；JDK9+ 默认 G1 | [[7-JVM内存与GC]] |
| OOM 怎么排查 | `-XX:+HeapDumpOnOutOfMemoryError` 抓 dump → MAT 看支配树找大对象 | [[8-JVM调优与故障排查]] |
| CPU 100% 怎么排查 | `top -Hp` 找线程 → `printf %x` 转十六进制 → `jstack` 定位栈 | [[8-JVM调优与故障排查]] |
| 虚拟线程何时可用 | **Java 21 起正式支持**，适合高并发 IO，**不要池化** | [[9-Java版本特性]] |

## 四、核心概念最小记忆集

| 概念 | 精确定义 | 常见误解 |
|---|---|---|
| **值传递** | Java **只有值传递**；对象传递的是引用的副本 | 以为"对象是引用传递" |
| **类型擦除** | 泛型信息在编译后被擦除，运行时不可见 | 以为运行时能拿到 `List<String>` |
| **静态分派 / 动态分派** | 重载在编译期定；重写在运行期按实际类型定 | 混为一谈 |
| **happens-before** | 可见性与有序性的判定规则，**非时间顺序** | 以为先执行就一定可见 |
| **锁升级** | 偏向 → 轻量级 → 重量级，**不可逆** | 以为可以降级 |
| **CLH 队列** | AQS 的等待队列（FIFO 双向链表变体），线程在此 `park` | 以为是自旋锁队列 |
| **CAS** | 比较并交换，硬件原子指令；有 ABA 与自旋开销 | 以为能替代所有锁 |
| **TLAB** | 线程本地分配缓冲，减少堆分配的同步竞争 | 以为是独立内存区 |
| **可达性分析** | 从 GC Roots 出发标记，不可达即可回收 | 以为是引用计数 |
| **Card Table** | 记忆集实现，用于**跨代引用**的增量 GC 扫描 | —— |
| **STW** | Stop-The-World，GC 时暂停用户线程 | 以为只有 Full GC 才有 |
| **TLAB / 逃逸分析 / 标量替换** | JIT 优化，让对象不必都在堆上分配 | 以为对象一定在堆上 |
| **AQS state** | `volatile int`，独占/共享模式下语义不同 | 以为只是个计数 |
| **Bean 三级缓存** | `singletonObjects`/`earlySingletonObjects`/`singletonFactories` | 以为只是为了"提前暴露对象" |

> [!warning] 六个最经典的面试陷阱
> 1. **"Java 是引用传递"** —— 错。**只有值传递**，对象传的是引用地址的副本（所以能改内容、不能改指向）。
> 2. **"`volatile` 能保证 `i++` 线程安全"** —— 不能。它只保证可见性与有序性，`i++` 是复合操作。
> 3. **"用过 `Executors.newFixedThreadPool` 就没问题"** —— 它用**无界队列**，任务堆积会 OOM；生产要手动建 `ThreadPoolExecutor`。
> 4. **"现在用偏向锁"** —— 偏向锁在较新 JDK 中**默认禁用/已废弃**，答题要说清趋势。
> 5. **"有循环依赖加个 `@Lazy` 就行"** —— 构造器注入的循环依赖 Spring 也解决不了；Spring Boot 2.6+ 默认直接禁止。
> 6. **"Full GC 频繁就是因为内存不够"** —— 也可能是**元空间泄漏、大对象直接晋升、`System.gc()` 被调用、堆参数不合理**。

## 五、版本演进速览

| 版本 | 里程碑 | 为什么重要 |
|---|---|---|
| **Java 8** | Lambda、Stream、`Optional`、接口 `default`、`Metaspace` 取代永久代、`HashMap` 引入红黑树 | **绝大多数存量项目的基线**，面试默认假设 |
| Java 9 | 模块系统 JPMS、`List.of`、G1 成为默认 GC | 模块化带来反射封装限制 |
| Java 11 | `var`、`HttpClient`（标准）、ZGC（实验） | **上一个 LTS** |
| Java 17 | 密封类、记录类、模式匹配 `instanceof`、**强封装 JDK 内部 API 默认生效** | **Spring Boot 3.x 的最低要求** |
| **Java 21** | **虚拟线程**、记录模式、switch 模式匹配、分代 ZGC、结构化并发（预览） | **当前主流 LTS**，并发模型的分水岭 |
| Java 25 | 最新 LTS，语言与运行时继续演进 | 新项目选型参考 |

> [!note] 本系列的口径
> 以 **Java 8 / 17 为基线**表述（面试默认问到 8，工程默认用 17+），涉及 **Java 21 虚拟线程**、**Java 25** 的地方会明确标注版本。
> 详细特性与代码示例见 [[9-Java版本特性]]。
