AbstractOwnableSynchronizer（AOS）：独占锁归属的基类
AbstractOwnableSynchronizer 是 JUC 并发框架底层的一个非常小巧但至关重要的抽象类。 ^Lbg3PH6m

3. AOS 的关键作用 ^4I7kxHIu

1、实现可重入性（Reentrancy）判断：
当一个线程尝试调用 lock() 时，AQS 的独占逻辑（如 tryAcquire）会通过 getExclusiveOwnerThread() == Thread.currentThread() 判断当前线程是否就是锁的持有者：

如果是同一线程，则认定为重入，直接对 state 计数累加，无需阻塞排队。

如果不是，则进入 CAS 竞争或加入等待队列。 ^oXkxEkX5

2、死锁排查与线程监控（Diagnostics）：
由于 AOS 明确记录了具体是哪个 Thread 占有了锁，JVM 诊断工具（如 VisualVM、JConsole、jstack）在导出 Thread Dump 时，能够精确打印出当前锁被哪个线程独占（例如 Locked ownable synchronizers: <0x...> 标识），极大地方便了线上排查死锁与高耗时卡顿。 ^s9mXqBfO

ReadWriteLock：读写分离的高效并发锁
ReadWriteLock 是一个读写锁的门面接口，维护了一对关联锁：一个用于只读操作的读锁（ReadLock），一个用于写入操作的写锁（WriteLock）。 ^VUPCMbOm

4. 适用场景
适用于“读多写少”的业务场景（如系统的基础配置缓存、用户白名单列表等），能将单纯排他的读吞吐量提升数倍。 ^91fUgWPP
