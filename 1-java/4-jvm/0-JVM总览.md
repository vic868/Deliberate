## 三、30 秒速查表

| 问题 | 一句话答案 | 详见 |
|---|---|---|
| 运行时数据区有哪几块 | 线程私有：PC、虚拟机栈、本地方法栈；共享：堆、方法区（另有直接内存不在规范内） | [[1-JVM内存区域与对象布局]] |
| 唯一不会 OOM 的区域 | **程序计数器** | [[1-JVM内存区域与对象布局]] |
| 方法区与永久代/元空间 | 方法区是**规范**，永久代（堆内）与元空间（本地内存）是**实现**；JDK8 起改为 Metaspace | [[1-JVM内存区域与对象布局]] |
| 为什么要换成元空间 | 永久代大小难估、PermGen OOM 频发、便于与 JRockit 合并 | [[1-JVM内存区域与对象布局]] |
| 对象怎么分配 | 类加载检查 → 分配（**指针碰撞/空闲列表**）→ 零值 → 对象头 → `<init>`；并发靠 **CAS** 或 **TLAB** | [[1-JVM内存区域与对象布局]] |
| TLAB 是什么 | 线程在 Eden 里的私有分配区，**免同步**；用完再申请（可能浪费） | [[1-JVM内存区域与对象布局]] |
| 对象内存布局 | 对象头（**Mark Word** + 类型指针）+ 实例数据 + 对齐填充（8 字节对齐） | [[1-JVM内存区域与对象布局]] |
| 对象一定在堆上吗 | 不一定：**逃逸分析**后可栈上分配/标量替换（是优化，不改变语义） | [[5-JIT编译与运行时优化]] |
| 怎么判断对象可回收 | **可达性分析**（GC Roots），不用引用计数 | [[2-GC机制深度]] |
| 新生代为什么用复制 | 对象**朝生夕死**，复制量小、无碎片、分配用指针碰撞；Eden:S0:S1 = 8:1:1 | [[2-GC机制深度]] |
| 三色标记会漏标吗 | 会，需靠**增量更新（CMS）**或**原始快照 SATB（G1）**解决 | [[2-GC机制深度]] |
| 卡表干什么 | 记录**跨代引用**的脏卡，让 Minor GC 不必扫整个老年代 | [[2-GC机制深度]] |
| 安全点是什么 | STW 的停靠点；`int` 长循环不触发安全点会导致停顿拉长 | [[2-GC机制深度]] |
| 收集器怎么选 | 吞吐优先 Parallel；低延迟 **G1**（JDK9+ 默认）；超大堆毫秒级 **ZGC**；CMS 已移除 | [[2-GC机制深度]]、[[6-JVM参数与调优实战]] |
| 双亲委派为什么需要 | **安全**（防核心类被冒充）+ **避免重复加载** | [[3-类加载机制与字节码]] |
| 什么时候要打破双亲委派 | SPI/JDBC（线程上下文类加载器）、Tomcat 应用隔离、热部署、OSGi | [[3-类加载机制与字节码]] |
| 类的唯一性由什么决定 | **类加载器 + 全限定名**；不同加载器加载同名类会 `ClassCastException` | [[3-类加载机制与字节码]] |
| 为什么要预热 | 热点代码需被 JIT 编译；**压测必须预热 + 用 JMH** | [[5-JIT编译与运行时优化]] |
| 最重要的 JIT 优化 | **方法内联**（其他优化的前提）；方法过大会拒绝内联 | [[5-JIT编译与运行时优化]] |
| Code Cache 满了会怎样 | JIT **停止编译**，性能骤降（表现为"跑一段时间变慢"） | [[5-JIT编译与运行时优化]] |
| 堆是不是越大越好 | 不是：堆 ≳ 32G 会**关闭压缩指针**，指针膨胀反而更慢 | [[1-JVM内存区域与对象布局]] |
| CPU 100% 怎么查 | `top -Hp` → `printf %x` → `jstack` 定位线程栈；先用 `jstat` 排除 GC | [[7-JVM故障排查实战]] |
| OOM 却看不到 Java 异常 | 容器 OOMKilled 超的是**总内存**（堆外），应**减小** `-Xmx` | [[7-JVM故障排查实战]] |
| 判断是否真泄漏 | Full GC 后老年代**仍居高不下** → 基本确认泄漏 | [[7-JVM故障排查实战]] |
| 生产必开的参数 | `-XX:+HeapDumpOnOutOfMemoryError`、`MaxMetaspaceSize`、GC 日志 | [[6-JVM参数与调优实战]] |

## 四、核心概念最小记忆集

| 概念 | 精确定义 | 常见误解 |
|---|---|---|
| **PC 寄存器** | 当前线程执行字节码的行号 | 以为也会 OOM |
| **栈帧** | 局部变量表 + 操作数栈 + 动态链接 + 返回地址 | 与"栈"混为一谈 |
| **Metaspace** | JDK8 起方法区的实现，在**本地内存** | 以为还在堆里 |
| **直接内存** | NIO 的堆外内存，受 `MaxDirectMemorySize` 约束 | 以为不受任何限制 |
| **TLAB** | 线程私有分配缓冲，免同步 | 以为是独立内存区 |
| **Mark Word** | 对象头中复用位，存 hashCode/年龄/锁状态 | 以为是固定结构 |
| **压缩指针** | 堆 < 32G 时用 32 位表示引用，省内存 | 忽视它对大堆的影响 |
| **可达性分析** | 从 GC Roots 遍历，不可达即可回收 | 以为是引用计数 |
| **三色标记** | 黑（已完成）/灰（待处理）/白（未访问） | 不知道会漏标 |
| **SATB** | 原始快照，G1 用；以"断开的旧引用"为根重扫 | 与增量更新混淆 |
| **卡表** | 记录跨代引用脏卡的记忆集实现 | 以为是缓存 |
| **安全点** | STW 时线程必须到达的停靠位置 | 以为任意位置都能停 |
| **双亲委派** | 先让父加载器加载 | 以为子加载器先加载 |
| **分层编译** | 解释器 + C1 + C2 五层协作 | 以为只有 C1/C2 |
| **逃逸分析** | 判断对象是否逃出方法/线程作用域 | 以为改变了 Java 语义 |
| **去优化** | 已编译代码失效回退解释执行 | 不知道它会导致"变慢" |

> [!warning] 六个最经典的面试陷阱
> 1. **"对象一定分配在堆上"** —— 逃逸分析后可栈上分配/标量替换，但这是**优化**，不能依赖。
> 2. **"永久代就是方法区"** —— 方法区是**规范**，永久代/元空间是实现；JDK8 已改用元空间（本地内存）。
> 3. **"GC 后内存不降就是堆太小"** —— **Full GC 后仍不降**更可能是**真泄漏**。
> 4. **"容器 OOMKilled 就加 `-Xmx`"** —— 超的是总内存，往往要**减小** `-Xmx`。
> 5. **"堆越大越快"** —— 超过 32G 关闭压缩指针、GC 停顿也可能变长。
> 6. **"代码跑一会儿变慢是玄学"** —— 常见于 **Code Cache 打满、去优化、GC、锁膨胀**，都是可观测的。
