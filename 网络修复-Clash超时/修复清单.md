# Clash Verge 所有节点超时 — 修复清单

> 诊断日期：2026-08-11
> 现象：Clash Verge 里所有节点延迟测试/连接全部 timeout，浏览器开代理后无法访问国外网站。

---

## 一、根因结论

问题**不在 Clash Verge 本身**，而是电脑上残留了一个 **sing-box 网络系统扩展**（SFMExtension），它抢占了网络：

- 它创建了虚拟网卡 `utun4`（IP `172.18.0.1`），并把**系统默认路由**和 **DNS** 全部劫持走（DNS 指向 `172.18.0.2`，返回 fake-ip `198.18.x.x`）。
- 但电脑上**并没有安装 sing-box 应用**（`/Applications` 里找不到）→ 这是一个**孤儿扩展**，没有配置，收下流量后直接丢弃（黑洞）。
- Clash Verge 拨节点时，出站流量被劫持进这个黑洞 TUN → 握手失败 `EOF` → 所以所有节点都超时。

**证据链（排查时的关键输出）：**

```text
# 默认路由被劫持到 utun4（连 1.1.1.1 都进 utun4）
route -n get 1.1.1.1
  interface: utun4

# DNS 被劫持，返回 fake-ip
dig @172.18.0.2 www.google.com A +short
  198.18.0.129

# 直连（不走任何代理）访问 Google 也失败 → 说明是系统级劫持，不是 Clash 的问题
curl https://www.google.com/generate_204
  code=000

# 系统扩展列表：sing-box 扩展处于 enabled + active
systemextensionsctl list
  * * 287TTNZF8L io.nekohasekai.sfavt.system (1.13.15/1) SFMExtension [activated enabled]

# 残留进程：sing-box 扩展以 root 运行，但 /Applications 里没有对应应用
ps -p 1018
  root  /Library/SystemExtensions/.../io.nekohasekai.sfavt.system
```

---

## 二、修复步骤

### 方案 A：图形界面操作（推荐，无需命令）

1. 打开 **系统设置**（System Settings）。
2. 点击 **通用**（General）→ **登录项与扩展**（Login Items & Extensions）。
3. 进入 **网络扩展**（Network Extensions）分类。
4. 找到名为 **SFMExtension**（标识符 `io.nekohasekai.sfavt.system`，来自 sing-box）的条目。
5. 将其**关闭**（Toggle 关掉），或点击移除。
6. 系统可能要求输入密码或重启，按要求操作。
7. 删除后验证（见第三节）。

### 方案 B：终端命令（在你自己终端执行）

打开「终端」（Terminal.app），逐条执行：

```bash
# 1) 卸载 sing-box 网络系统扩展（需输入管理员密码）
sudo systemextensionsctl uninstall 287TTNZF8L io.nekohasekai.sfavt.system

# 2) 确认扩展已不存在（应看不到 SFMExtension 或显示为已卸载）
systemextensionsctl list
```

> 如果第 1 步报错提示需要先重启或解除阻止，先执行：
> ```bash
> sudo systemextensionsctl reset
> ```
> 然后再重新执行第 1 步。

## 三、验证（删除扩展后）

```bash
# 1) utun4 虚拟网卡应消失
ifconfig utun4          # 预期报错 no such interface

# 2) 默认路由应回到你的路由器（en0 / 192.168.0.1）
netstat -rn -f inet | grep '^default'

# 3) DNS 恢复为路由器/DHCP（不再是 172.18.0.2）
scutil --dns | head -20

# 4) 不带代理直连 Google 应成功
curl -m 10 -sS https://www.google.com/generate_204 -o /dev/null -w "code=%{http_code}\n"
# 预期输出：code=204

# 5) 重启 Clash Verge，延迟测试节点
```

## 四、其他建议（避免再次冲突）

这台电脑上还有别的代理工具，建议只保留一个，避免互相抢网络：

| 工具 | 状态 | 建议 |
|---|---|---|
| Clash Verge（mihomo） | 运行中，7891 | **保留**（你要用的） |
| sing-box 扩展 | 已卸载 | 不用再装 |
| ShadowsocksX-NG（ss-local，1086） | 后台运行 | 如不用，退出并移除 |
| ProtonVPN 扩展 | 已安装未启用 | 如不用可移除 |

> 另外确认 Clash Verge 里「Tun 模式」和「系统代理」只开其中一个即可，两者都开也容易出问题。

## 五、如果删除扩展后 Clash 节点仍超时

说明问题还叠加了其他原因，按顺序排查：

```bash
# 1) 确认系统代理确实指向 7891
scutil --proxy | grep -E 'Enable|Port'

# 2) 确认 7891 端口活着（应该显示 succeeded）
nc -vz 127.0.0.1 7891

# 3) 走代理访问国内网站（应 200，说明代理通路正常）
curl -x http://127.0.0.1:7891 -m 10 -sS https://www.baidu.com -o /dev/null -w "code=%{http_code}\n"

# 4) 走代理访问国外网站（应 204/200，而不是 timeout）
curl -x http://127.0.0.1:7891 -m 10 -sS https://www.google.com/generate_204 -o /dev/null -w "code=%{http_code}\n"

# 5) 若第 4 步失败，看核心日志里的拨号错误
tail -50 ~/Library/Application\ Support/io.github.clash-verge-rev.clash-verge-rev/service-logs/service/service_latest.log

# 6) 若日志显示所有节点都 EOF，则可能是订阅节点集体失效：
#    - 去机场官网在线测速确认节点是否还活着
#    - 重新导入订阅（Clash Verge 订阅页点更新）
```
