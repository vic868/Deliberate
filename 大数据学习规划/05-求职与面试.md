# 🎤 大数据求职与面试（第 3 周）

> [!abstract] 策略
> 你最终目标是 **AI 应用负责人**，大数据是**加分组合**。
> 面试准备重点：① Flink 深问不倒 ② 实时数仓能画能讲 ③ 能讲清"数据 + AI"的复合价值。

## 项目 STAR 复盘（先做这个）

> [!tip] STAR 模板
> - **S** 背景：项目解决什么业务问题，数据量多大（量级要说清）
> - **T** 任务：我负责哪部分（实时链路 / Flink 任务 / 数仓建模）
> - **A** 行动：具体技术方案（Flink + Kafka + Doris、Checkpoint、CDC）
> - **R** 结果：**量化**（吞吐、延迟、成本下降、故障率）

- [ ] 复盘 2 个代表作，填 STAR 卡片
- [ ] 每个项目准备 3 个"追问深挖"点（细节必须真实可讲）

## Flink 高频面试题

- [ ] Watermark 怎么解决乱序？迟到数据怎么办？
- [ ] Checkpoint 原理？Barrier 对齐？
- [ ] 端到端精确一次怎么实现？
- [ ] 背压怎么识别和解决？
- [ ] 数据倾斜怎么处理？
- [ ] Flink vs Spark Streaming？
- [ ] 状态后端怎么选？状态膨胀怎么办？
- [ ] CDC 同步链路怎么设计？

> 详细答案方向见 [[02-Flink补课]]

## 实时数仓面试题

- [ ] 数仓分层讲讲？实时和离线口径怎么统一？
- [ ] Doris vs ClickHouse vs StarRocks 怎么选？
- [ ] Kafka → Flink → Doris 链路有什么坑？（乱序、幂等、延迟）
- [ ] 实时指标怎么保证不丢不重？

## 复合加分题（大数据 × AI）

- [ ] "实时特征 + AI 推理"架构怎么设计？（特征服务、在线/离线一致性）
- [ ] "数据平台如何支撑 RAG 知识库"？（日志、文档、向量化链路）
- [ ] 你如何用 Flink 做实时数据，喂给大模型应用？

> [!tip] 这是你的**杀手锏**
> 大部分 AI 候选人不懂数据平台，大部分大数据候选人不懂 AI。
> 你把两者打通，就是"AI 应用负责人"最稀缺的画像。

## 简历要点

- 技术栈：Flink、Flink CDC、Kafka、Spark、Hive、Doris/ClickHouse、HDFS
- 亮点句式：`实时链路延迟 < 5s` / `吞吐 X 万/s` / `数据同步准确率 99.99%`
- 与 AI 项目并列：RAG + 实时数仓 = 完整数据智能
