## 万能答题框架

```mermaid
flowchart LR
    A[①需求澄清] --> B[②场景量级] --> C[③功能拆分]
    C --> D[④技术选型] --> E[⑤架构图]
    E --> F[⑥核心模块] --> G[⑦数据流]
    G --> H[⑧瓶颈优化] --> I[⑨容灾降级] --> J[⑩演进]
```

> [!important] 三个必做动作
> 1. **先问清楚**：QPS 多少？数据量多大？读写比例？能接受最终一致吗？（**不问就答 = 减分**）
> 2. **先算量级**：日活 × 人均请求 ÷ 86400 → 峰值 ×3~5；存储按 3~5 年估算
> 3. **先画图再讲细节**：面试官要的是结构感

### 必讲细节清单
- 技术选型**理由**（不是"我们用了 Redis"，而是"为什么用 Redis"）
- 单点在哪、怎么消除
- 瓶颈在哪、怎么扩展（**无状态化**是关键）
- 缓存策略、一致性方案
- 降级与兜底
- 数据量与成本量级

## 经典设计题

### 1. 秒杀系统
**要点**：层层过滤 → 前端限流（按钮置灰）→ 网关限流 → **Redis 预扣库存（Lua 原子）** → MQ 异步下单 → 数据库扣减
**关键**：超卖（Lua/乐观锁）、少卖（补偿）、防刷（风控）、热点隔离（独立集群）、页面静态化、URL 加盐

### 2. 短链系统
**要点**：发号器（雪花/自增）→ **Base62 编码** → 存储映射 → 302 重定向（统计）/ 301（缓存）
**关键**：分库分表、缓存预热、布隆过滤器防无效、自定义短码

### 3. IM 即时通讯
**要点**：长连接网关（Netty/WebSocket）→ 消息 ID（有序）→ **离线消息**（拉取 + 推送结合）→ 消息存储（会话维度分表）→ 已读回执
**关键**：多端同步、消息时序、群聊扩散写 vs 扩散读、连接路由表

### 4. 订单系统
**要点**：状态机（待支付→已支付→已发货→完成/关闭）、幂等、超时关单（延迟消息/定时扫表）、分库分表（按 user_id）、对账

### 5. 支付系统
**要点**：幂等（商户订单号唯一）、状态机、**对账**（日终）、异步通知 + 主动查询兜底、账务双录（复式记账）、资金安全

### 6. 库存系统
**要点**：防超卖（`update stock = stock - 1 where stock >= 1` 或 Redis+Lua）、库存分层（活动库存/实物库存）、预占与释放

### 7. 排行榜
**要点**：**Redis ZSet**（`ZINCRBY` / `ZREVRANGE`）；海量数据分桶（按分数段/时间）+ 定期合并落库

### 8. Feed 流
**要点**：推模式（写扩散，读快）、拉模式（读扩散，写快）、**推拉结合**（大 V 拉、普通用户推）；分页用游标

### 9. 附近的人
**要点**：**Redis GEO**（geohash）或 PostGIS；按距离排序、分页、格子划分

### 10. 分布式任务调度
**要点**：调度中心 + 执行器、注册发现、分片广播、失败重试、幂等、日志回溯（XXL-JOB 模型）

### 11. 网关设计
**要点**：路由、鉴权、限流、熔断、灰度、日志埋点、协议转换；**必须无状态 + 可水平扩展**

### 12. 海量设备接入（IoT 平台）
**要点**：**Netty 长连接网关（无状态）** → 设备 ID 路由表（Redis）→ MQ 削峰 → 业务服务 → 时序存储
**关键**：心跳保活、断线重连（退避+抖动，防重连风暴）、指令下发幂等与回执、固件 OTA 灰度、设备影子/离线指令缓存、多租户隔离

## 高并发通用套路

| 层次 | 手段 |
|---|---|
| 前端 | CDN、静态化、合并请求、懒加载 |
| 网关 | 限流、熔断、鉴权、缓存 |
| 应用 | **无状态 + 水平扩展**、异步化、线程池隔离、批量 |
| 缓存 | 多级缓存（本地 + Redis）、热点打散 |
| 数据库 | 索引优化、读写分离、分库分表、**最终一致** |
| 异步 | MQ 削峰、任务队列 |
| 兜底 | 降级、限流、排队、兜底数据 |
