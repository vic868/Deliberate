# 🔴 07 · Redis 与缓存

> 返回 [[00-总览与使用说明]]

---

## 一、基础

| 问题 | 得分骨架 |
|---|---|
| Redis 为什么快 | 纯内存、**单线程无锁无竞争**、IO 多路复用（epoll）、高效数据结构、RESP 协议简单 |
| 单线程还快？ | 瓶颈在内存和网络不在 CPU；6.0 后网络 IO 多线程但**命令执行仍单线程** |
| 数据结构与场景 | String（缓存/计数器/分布式锁）、Hash（对象）、List（消息队列/时间线）、Set（去重/共同好友）、**ZSet（排行榜/延迟队列）**、Bitmap（签到）、HyperLogLog（UV 估算）、GEO（附近的人）、Stream（消息队列） |
| 底层结构 | SDS、ziplist/listpack、quicklist、**跳表（ZSet）**、intset、hashtable |
| 过期策略 | 惰性删除 + **定期随机删除** |
| 内存淘汰 | noeviction / LRU / LFU / random / ttl；**Redis 的 LRU 是近似 LRU**（采样） |

## 二、持久化

| 方式 | 说明 | 优缺点 |
|---|---|---|
| **RDB** | 快照，`bgsave` fork 子进程写 | 文件小、恢复快；**可能丢数据** |
| **AOF** | 追加写命令，`everysec`/`always`/`no` | 数据安全；文件大、恢复慢 |
| 混合持久化 | 4.0+，RDB 全量 + AOF 增量 | 推荐 |
| fork 问题 | fork 耗时与内存成正比；**写时复制**导致内存可能翻倍 |

---

## 三、高可用与集群

| 模式 | 说明 |
|---|---|
| 主从 | 读写分离；异步复制，**故障需手动切换** |
| 哨兵 Sentinel | 监控 + 自动故障转移 + 通知；至少 3 个哨兵 |
| **Cluster** | 分片，**16384 个槽**；CRC16 取模；支持多 key 操作需同槽（可用 hash tag `{}`） |
| 脑裂 | 网络分区导致双主 → 加 `min-replicas-to-write` 缓解 |

---

## 四、缓存三大问题 `#高频`

| 问题 | 原因 | 解法 |
|---|---|---|
| **穿透** | 查不存在的数据，请求全打到 DB | 缓存空值（短 TTL）、**布隆过滤器**、参数校验 |
| **击穿** | 热点 key 过期瞬间大量并发 | 互斥锁重建、**逻辑过期**（不设 TTL，异步刷新）、热点永不过期 |
| **雪崩** | 大量 key 同时过期 / Redis 宕机 | **过期时间加随机**、多级缓存、限流降级、集群高可用 |

## 五、缓存与数据库一致性 `#高频`

**推荐方案**：
1. **Cache Aside（旁路缓存）**：读时未命中查 DB 回填；写时**先更新 DB 再删除缓存**
2. 为什么是删除不是更新：避免并发写导致脏数据；删除更简单
3. 为什么先更新 DB 再删缓存：并发下"先删缓存再更新 DB"更容易脏
4. **延迟双删**：更新 DB 后删缓存，延迟几百 ms 再删一次（应对主从延迟）
5. **Canal 订阅 binlog** 异步删缓存 → 解耦、可靠
6. **最终一致 + 兜底**：设 TTL、定时对账

> [!tip] 回答要点
> 承认**强一致代价极高**，业务上一般接受**最终一致**。
> 关键是讲清「并发场景下会出现什么脏数据 + 你怎么兜底」。

## 六、分布式锁 `#高频`

```bash
SET key value NX PX 30000     # value 必须唯一（如 UUID）
# 释放用 Lua 脚本：先比较 value 再删除（防误删）
```

| 问题 | 说明 |
|---|---|
| 为什么需要唯一 value | 防止 A 的锁超时后被 B 拿到，A 执行完误删 B 的锁 |
| 锁续期 | Redisson **看门狗**：默认 30s，每 10s 续期 |
| RedLock 争议 | 多节点加锁；**Martin Kleppmann 质疑其正确性**（GC 停顿、时钟漂移）；能不用就不用 |
| 更好的方案 | 用 fencing token（递增序号）或让下游做幂等 |
| 其他 | ZooKeeper 临时顺序节点（CP，可靠性高但性能低） |

## 七、实战问题

- **大 key**：value 过大（>10KB）→ 拆分、压缩、异步删除（`unlink`）
- **热 key**：本地缓存、多副本打散、读写分离
- **Pipeline**：批量减少 RTT（**非原子**）
- **Lua 脚本**：原子执行多个命令
- **事务**：MULTI/EXEC，**不支持回滚**
- **慢查询**：`slowlog`、避免 `keys *`（用 `scan`）
- **缓存预热**：启动或定时任务提前加载
