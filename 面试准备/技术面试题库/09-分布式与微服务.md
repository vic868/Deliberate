## 一、理论基础

| 问题 | 得分骨架 |
|---|---|
| CAP | 一致性 / 可用性 / 分区容错性**三选二**；分布式系统 P 必须保，所以是 **CP vs AP** 之争 |
| BASE | 基本可用、软状态、最终一致；**对 CAP 的工程妥协** |
| 为什么不能同时满足 C 和 A | 网络分区时，要么拒绝服务保一致（CP），要么返回旧数据保可用（AP） |

---

## 二、分布式事务 `#高频`

| 方案 | 原理 | 优点 | 缺点 |
|---|---|---|---|
| **2PC** | 准备 + 提交，协调者 | 强一致 | 同步阻塞、协调者单点、数据不一致窗口 |
| **TCC** | Try 预留 → Confirm → Cancel | 灵活、性能较好 | **代码侵入大**，要处理空回滚/悬挂/幂等 |
| **Saga** | 长事务拆成多个本地事务 + 补偿 | 适合长流程 | 无隔离性，补偿逻辑复杂 |
| **本地消息表** | 本地事务写消息表 → 异步投递 → 重试 | 简单可靠、最终一致 | 依赖 DB、需要轮询 |
| **事务消息** | MQ 半消息 + 回查 | 解耦好 | 依赖 MQ 支持 |
| **Seata AT** | 全局锁 + undo log 自动回滚 | **无侵入** | 全局锁性能损耗 |

> [!tip] 回答套路
> 先问「**业务能接受最终一致吗？**」能 → 本地消息表/MQ 事务；
> 不能 → TCC/Seata。再补一句「**所有方案都要幂等 + 对账兜底**」。

## 三、分布式 ID

| 方案 | 说明 |
|---|---|
| UUID | 本地生成、无网络开销；**无序**（影响 B+ 树插入）、占空间 |
| 数据库自增 | 简单；有性能瓶颈、暴露信息量 |
| 号段模式 | 一次取一批（如 1000 个）缓存在内存；**推荐**，美团 Leaf |
| **雪花算法** | 64 位：符号 + 时间戳 + 机器 ID + 序列号；**趋势递增**；**依赖时钟** |
| 时钟回拨怎么办 | ① 等待追平 ② 用备用机器 ID ③ 抛异常报警 ④ 用 NTP 校准 + 检测 |

## 四、限流 / 熔断 / 降级

| 算法 | 特点 |
|---|---|
| 固定窗口 | 简单；**临界问题**（两个窗口边界可能翻倍） |
| 滑动窗口 | 解决临界问题；需存时间片 |
| 漏桶 | 恒定速率流出，**削峰** |
| **令牌桶** | 恒定速率放令牌，允许突发（**Guava RateLimiter / Sentinel 默认**） |

- **熔断**：Closed → Open → Half-Open（失败率阈值触发，快速失败保护下游）
- **降级**：返回兜底数据、关闭非核心功能
- **隔离**：线程池隔离 / 信号量隔离（防止一个依赖拖垮全链路）
- 工具：Sentinel、Hystrix（停更）、Resilience4j

## 五、微服务组件

| 能力 | 常见方案 |
|---|---|
| 注册中心 | Nacos、Eureka、Consul、ZooKeeper |
| 配置中心 | Nacos、Apollo |
| 网关 | Spring Cloud Gateway、Zuul、Kong、Nginx |
| RPC | Dubbo、Feign、gRPC |
| 负载均衡 | Ribbon、LoadBalancer；轮询/随机/一致性哈希/最小连接 |
| 链路追踪 | SkyWalking、Zipkin、Jaeger |
| 服务保护 | Sentinel |
| 分布式锁 | Redis、ZooKeeper |
| 分布式任务 | XXL-JOB、Elastic-Job |

**注册中心选型**：Nacos（AP+CP 可切、功能全，**推荐**）、Eureka（AP，已停更）、ZK（CP，写性能差）

**服务雪崩**：一个服务慢 → 线程堆积 → 上游也慢 → 全链路崩溃
**解法**：超时 + 重试（谨慎）+ 熔断 + 隔离 + 限流

## 六、高可用与容灾

- 集群 / 多副本 / 主从 / 多活（同城双活、异地多活）
- 健康检查与自动故障转移
- 灰度发布、蓝绿部署、回滚预案
- 幂等设计（所有写接口）、对账与补偿任务
- 容量评估与压测、全链路压测
- 监控告警：指标（Prometheus）+ 日志（ELK）+ 链路（SkyWalking）

---

## 七、常见场景题

- **接口幂等**：token 机制 / 唯一索引 / 状态机 / 分布式锁
- **分布式限流**：Redis + Lua（滑动窗口/令牌桶）
- **跨服务数据一致性**：本地消息表 + 定时对账
- **服务优雅上下线**：注册中心摘除 → 等待在途请求 → 停止
- **灰度发布**：按用户/流量比例路由
