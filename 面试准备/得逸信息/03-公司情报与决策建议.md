# 🏢 得逸信息 · 公司情报与决策建议

> 返回 [[00-JD与匹配分析]]

> [!danger] 最重要的一条结论（先说）
> **得逸信息是「汉得信息」的控股子公司，本质是「软件外包 / 人力服务 + IT 实施」公司。**
> 这直接决定了这个"技术经理"岗位的**真实性质**——详见第三节。
> **这不是一家做自研产品的公司，你去管的外包团队，很可能和你自己处于同一类身份。**

> [!important] 关键细节：旗下有一家「得逸劳务派遣有限公司」
> 一个集团里专门设**劳务派遣**公司，是**人力外包商业模式**的典型标志。
> 结合得逸信息经营范围里的"**以服务外包方式从事生产流程、生产工段企业经营管理**"，
> 这个集团的业务形态非常清楚：**做 IT 人力/项目外包**。

**经营范围（原文摘录）**：信息技术、网络科技、电子科技、计算机软件、智能化科技领域内的技术咨询、技术服务、技术开发、技术转让，**以服务外包方式从事生产流程、生产工段企业经营管理**，计算机系统集成，**计算机数据处理**，销售计算机软硬件及辅助设备。

> [!tip] 招聘平台上的行业标签是"计算机软件"、"1000-9999 人"、"未融资"
> — "未融资"是因为它是**上市公司的子公司**，不需要自己融资，不是"初创"的意思。
> — "1000-9999 人"符合外包公司的人力规模特征。

## 二、母公司汉得信息是什么（决定技术栈画像）

**上海汉得信息技术股份有限公司（HAND，股票代码 300170）**：
- 国内老牌 **IT 咨询与实施服务商**，起家于 **Oracle 实施**（官网"产品实施服务"栏第一位就是 **Oracle**，还有 SAP、Microsoft、SIEMENS）
- 主要业务：**ERP/管理软件实施、技术咨询、系统集成、运维**，客户以**大型企业**为主
- 行业覆盖：**智能制造、金融服务、流通贸易、零售、医药快消、公用事业、民航物流、电信**
- 自有产品线：SRM、费控、主数据管理（HMDM）、财务共享、物联网平台 HIoT 等

> [!success] 这条信息解释了这个 JD 里的所有"违和感"
> **为什么 JD 里 Oracle 排在 MySQL 前面？**
> → 因为汉得系的老本行就是 **Oracle 实施**，客户是传统大型企业（制造业/金融/公用事业），数仓底层大量是 Oracle。
>
> **为什么要求"对接、评审、细化"方案，而不是"从 0 设计"？**
> → 因为外包项目的方案往往来自**甲方或汉得的售前/架构团队**，技术经理负责**落地和守门**。
>
> **为什么既有 Oracle 又有 StarRocks/Doris？**
> → 典型场景：**帮传统企业做数仓现代化改造**——存量 Oracle，新建 Doris/StarRocks。
> 这是"数据中台/数仓升级"项目的标准形态，也是汉得这类实施商的主力业务。

## 三、这个"技术经理"岗位的真实性质 ⚠️

> [!danger] 你必须想清楚这件事，它影响你要不要接这个 offer

**JD 里"管理供应商外包团队"的三条职责（2/4/5），有两种完全不同的解释：**

| 解释 | 场景 | 含义 |
|---|---|---|
| **A. 你是甲方** | 得逸承接了某个大客户的数仓项目，你是得逸方项目负责人，管理**下游分包商** | 你确实是"甲方接口人"，有一定话语权 |
| **B. 你是乙方（更可能）** | 得逸把人派到客户现场（驻场），你负责管理**得逸自己的外包/派遣员工** | 你管的"外包"，本质就是**得逸自己的员工**，你只是最底层的现场管理者 |

> [!warning] 从 JD 的措辞判断，**B 的可能性更大**
> - 措辞是"**统筹供应商外包开发团队**"、"**对外包团队工作成果进行考核与管控**"
> - 但一家外包公司为什么会把"管供应商"当成核心职责？
> - **最合理的解释**：得逸承接的项目里，**自己出人力 + 再分包一部分给更小的供应商**，
>   或者得逸是**多层分包中的中间层**，你负责把下游的人管住、把活交出去。
> - 也可能：你的团队就是**得逸派遣到客户现场的人**，公司内部习惯性称之为"外包团队"。

**面试必须问清楚的问题**（见第五节），答案直接决定这个岗位值不值得去。

## 五、面试必须问清的问题（按重要性排序）

> [!important] 这几个问题问完，你就能判断这岗位值不值得去

### 🔴 第一优先级：岗位真实性

1. **"这个岗位是得逸自己的项目，还是派驻到客户现场的？需要长期驻场吗？"**
   - 如果驻场 → 你的工作地点、汇报关系、项目周期都可能不由你控制
2. **"我要管理的'外包团队'，是指得逸自己的开发人员，还是第三方的分包供应商？"**
   - ⭐ **这个问题最关键**，直接区分"甲方接口人"和"现场包工头"
3. **"团队现在多少人？内外部怎么构成？"**

### 🟠 第二优先级：技术与项目

4. **"客户/项目是什么行业？数仓底层是 Oracle 为主还是 Doris/StarRocks 为主？"**
   - 判断技术和你的 Doris 笔记匹配度
5. **"数仓是从 0 建设，还是接手已有的？数据量级大概多少？"**
6. **"现在最大的痛点是什么——性能、口径、还是交付质量？"**

### 🟡 第三优先级：待遇与稳定性

7. **"薪资范围是多少？结构是怎样的（底薪/绩效/项目奖金）？"**
8. **"项目周期多长？项目结束后人员怎么安排？"**
   - ⚠️ 外包岗的经典风险：**项目结束 = 待岗/被调配到别的项目**
9. **"这个岗位是新增还是替代离职者？"**
10. **"绩效考核怎么算？和项目回款挂钩吗？"**

## 六、决策建议：要不要去

### ✅ 值得去的理由

| 理由 | 说明 |
|---|---|
| **Doris/StarRocks 是真需求** | 你的 Doris 笔记体系（架构/建模/优化/湖仓）能直接用上，这是**真实的技能匹配** |
| **补上管理经验的短板** | 你缺的正是"管理"的正式经历（冠顿/智控都卡在这）。**外包管理是管理经验里最硬的一种**——管没汇报关系的人 |
| **汉得系平台背书** | 上市公司子公司，简历上"管理外包团队交付数据仓库项目"**含金量比纯开发高** |
| **传统企业数仓改造 = 稀缺经验** | Oracle → Doris 的迁移/共存经验，在制造业/金融数字化里是**刚需且难招** |
| **可能就是你现在最需要的"跳板"** | 从"后端开发"跳到"技术经理"，**这是你职业定位升级的关键一步** |

### ❌ 需要警惕的风险

| 风险 | 说明 | 应对 |
|---|---|---|
| **你可能不是"甲方"** | 如果得逸本身是外包方，你管的"外包"可能就是自己同事，**你只是个现场管理者，没有真正的甲方权力** | 面试问清（第五节问题 2） |
| **驻场风险** | 若派驻客户现场，工作地点/环境/汇报线都不确定 | 问清是否需要驻场 |
| **通勤 21.7 km** | 三家里最远；若叠加加班，时间成本很高 | 算清每天往返时间 |
| **薪资可能偏低** | 外包公司按人力成本倒推薪资；且 JD **未标薪资** | 先问薪资再投入 |
| **"抗压能力""保障交付"= 加班信号** | JD 职责 4 提到抗压能力和项目推进能力 | 问清工作节奏 |
| **项目结束的不确定性** | 外包岗典型风险 | 问项目周期与后续安排 |

### 🎯 我的建议

> [!tip] 结论：**值得去面试，但要用"尽调心态"去，不要一上来就投入感情**
>
> **理由**：
> 1. **它精准命中你的两个需求**——① 用上 Doris/数仓（你有真材实料）② **补上管理经验的正式头衔**（这是你目前最大的职业短板）
> 2. **面试本身就是免费的训练**——你正在准备冠顿/智控的负责人岗，**这场面完你的管理面会强一大截**
> 3. **风险是可控的**——第五节的问题问清楚，尤其是"管的是谁"和"薪资"，答案不合适就礼貌退出
>
> **但记住三条底线**：
> - ❌ **不要为了"经理"头衔接受明显降薪**——头衔不值钱，能力和钱才值钱
> - ❌ **不要在没问清是否驻场前投入太多面试轮次**
> - ✅ **要把它和冠顿/智控放在一起比**——你手上应该同时有多个选项，才能谈条件

### 📊 三家横向对比

| | 智控（ZKONG） | 冠顿 | **得逸信息** |
|---|---|---|---|
| 岗位 | Java 开发工程师 | 后端开发负责人 | **技术经理（数仓）** |
| 性质 | 纯开发 | 管理+技术 | **管理+技术（外包管理为主）** |
| 公司类型 | 产品（电子价签） | 产品（电子/硬件） | **IT 外包/实施（汉得子公司）** |
| 技术主场 | IoT、高并发 | 微服务治理 | **数仓、Doris、Oracle** |
| 管理权重 | 无 | 中 | **高（约 70% 职责）** |
| 管理经验要求 | 无 | 2 年 | **1 年+（硬性）** |
| 通勤 | 15.3 km | 15.3 km | **21.7 km** |
| 薪资 | 15-20K / ≤30K | 20-25K | **未知（必须问）** |
| 对你的短板补益 | 无 | 管理头衔 | **管理头衔 + 数仓经验** |
| 风险 | 降薪 | 薪资偏低 | **可能是驻场/外包身份** |

> [!important] 一句话总结
> **得逸这个岗位在"能力补益"上是最好的（管理 + 数仓双补），
> 但在"身份和稳定性"上是最需要警惕的（外包公司、可能驻场、通勤最远）。**
> **面试问清楚，再决定投入程度。**
