# 📘 第1章：大模型应用开发概述

> [!abstract] 原文开篇导语（已核对）
> LLM 应用开发入门，从零理解大模型是什么、能做什么、怎么调用。原文开篇即点明：大模型（LLM）本质上是一个接受文本输入、返回文本输出的函数；从工程角度不需要理解内部神经网络结构，只需要知道给它一段 Prompt，它会返回一段 Completion。

> [!tip] 一句话理解
> 把大模型当成一个「输入文字、输出文字」的远程函数，先学会怎么调它、怎么按字付费、怎么让它边生成边显示。

## 🧩 核心概念速记

| 概念 | 一句通俗解释 |
| --- | --- |
| Token | 模型眼里的「字」，既不是字符也不是单词；API 按它收费，中文通常比英文更费 |
| 上下文窗口 | 模型一次能看下的字数上限，超了最前面的内容就会被挤出去 |
| Temperature | 回答的「随机度旋钮」，调高更有创意、也更容易跑偏 |
| Messages 消息角色 | system 定规矩、user 提问题、assistant 是模型回的话；多轮对话就是这三类消息不断累积 |
| SSE 流式输出 | 像打字机一样一段段把字吐出来，不用等全部生成完才显示 |

> [!example] 1.2.1 Token —— 原文代码块与要点
> ```text
> 英文："Hello World" → ["Hello", " World"] → 2 tokens
> 中文："你好世界"     → ["你", "好", "世", "界"] → 大约 4 tokens
> 代码："const x = 1"  → ["const", " x", " =", " 1"] → 4 tokens
> ```
> **Token 的工程意义**（原文三条）：
> - API 按 Token 计费，输入和输出**分别计价**
> - 模型有最大上下文长度限制，原文举例 DeepSeek-chat 支持 **64K tokens**
> - Token 数量影响**响应速度和成本**
>
> **快速估算规则**（原文注明「不用装 tiktoken，这个精度够用」）：
> - 英文：`1 token ≈ 4 个字符`
> - 中文：`1 个汉字 ≈ 1.5–2 tokens`，按 `0.6 token/字` 估算
> - 代码：比普通文字消耗更多 token
