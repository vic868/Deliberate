# 📘 第2章：提示词工程

> [!abstract] 原文开篇导语（已核对）
> 怎么和大模型「说话」才能得到你想要的结果——原文称这是大模型应用开发中**最直接影响产品效果**的技能。同样一个问题，提问方式不同，输出质量可以差很多；原因很直接：模型是按字面理解你说的话的，含糊的指令会得到含糊的结果。

> [!tip] 一句话理解
> 别指望模型猜你的心思：把角色、任务、格式、示例都写清楚，输出才稳定可用。

## 🧩 核心概念速记

| 概念 | 一句通俗解释 |
| --- | --- |
| 角色设定 | 在 system 消息里先告诉模型「你是谁」，它才知道该用什么口气和知识范围 |
| Few-shot | 给几个示范样例，让模型照葫芦画瓢，比讲半天规则管用 |
| CoT 思维链 | 让模型把推理步骤写出来再给结论，别直接跳答案 |
| 结构化输出 | 要求返回 JSON 这类固定格式，程序才能直接解析 |
| withStructuredOutput | 让框架帮你约束输出格式，比自己写 Prompt + 容错解析稳得多（原文推荐） |
