# 📘 第8章：Workflow 工作流

> [!abstract] 原文开篇导语（已核对）
> 第七章的 Agent 适合任务路径不确定、需要模型自主规划的场景；Workflow 适合另一类场景：**执行步骤已知、顺序固定、需要稳定可控**——文章生成、代码审查、数据处理管道都属于这类。原文给出的核心区别是「谁来决定执行路径」：Workflow 由开发者预先定义，Agent 由模型决定。

> [!tip] 一句话理解
> 路线能提前画清楚就用工作流（稳、可复现）；路线得边走边定才用 Agent（灵、但难控）。

## 🧩 核心概念速记

| 概念 | 一句通俗解释 |
| --- | --- |
| Workflow | 步骤事先写死、顺序可控的流程，适合稳定重复的任务 |
| 条件工作流 | 根据上一步的结果决定接下来走哪条分支 |
| 并行工作流 | 几个互不依赖的节点同时跑，省总耗时 |
| Human-in-the-Loop | 在关键节点先暂停，等人确认或改完再继续往下走 |
| 断点恢复 | 把流程状态存盘，服务重启或人工审核后能从断点接着跑 |
