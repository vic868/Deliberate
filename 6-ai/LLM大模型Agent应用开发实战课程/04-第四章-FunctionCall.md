# 📘 第4章：Function Call

> [!abstract] 原文开篇导语（已核对）
> 让大模型从「只能说话」升级到「能调用工具干活」。原文称 Function Call 是大模型应用里**最有工程价值**的特性之一：客服系统、数据查询、自动化操作全靠它。没有它，模型只能靠训练时学到的知识回答，不知道今天的天气、你的订单状态、你数据库里的数据。

> [!tip] 一句话理解
> 模型不亲自干活，它只负责说「该调哪个工具、参数是什么」，真正执行由你的代码完成。

## 🧩 核心概念速记

| 概念 | 一句通俗解释 |
| --- | --- |
| Function Call | 模型输出一个「工具名 + 参数」的结构化请求，由应用代码执行后把结果喂回去 |
| Zod Schema | 用代码把工具参数的类型和含义写清楚，模型才知道每个字段该填什么 |
| ToolNode | LangGraph 里专门负责接住工具调用并执行的节点 |
| 幂等性 | 同一个操作重复跑几次结果都一样，防止网络重试造成重复下单/重复扣款 |
| SSE 推送工具状态 | 前端实时看到「正在查订单…」，不会以为页面卡死 |
