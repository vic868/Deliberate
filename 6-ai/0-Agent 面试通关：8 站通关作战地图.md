## 📌 第 1 站：概念与边界（立地基）

### 1. 最小核心定义

> [!tip] 核心金句 Agent 就是一个会调用工具的循环系统。
> 
>   
> 
> - **系统**：不是单次无状态调用。
>     
>       
>     
> - **循环**：能根据真实反馈（Observation）跑下一轮。
>     
>       
>     
> - **调用工具**：能真正触达并改变外部真实物理世界。
>     
>       
>     

### 2. 决策权“三判句”与组件过筛

用来秒杀「Agent / Chatbot / Workflow / RPA 区别」的判定标尺：

  

1. **谁来决定下一步？**
    
      
    
      
    
2. **能不能感知环境变化？**
    
      
    
      
    
3. **出错后自己会不会动态调整？**
    
      
    
      
    

|**类别**|**决策权归属**|**能否感知环境变化**|**出错能否自调**|**本质定性 MD**|
|---|---|---|---|---|
|**Chatbot**|用户决定|❌（仅文本交互）|❌|一问一答，失忆式交互|
|**Workflow**|人类工程师写死|❌（环境变了照流程走）|❌|固定管道，按图索骥|
|**RPA**|脚本代码写死|❌（按脚本点按钮）|❌|纯机械执行，无环境感知|
|**AI Agent**|**模型/系统自主决策**|**✅（能动态感知反馈）**|**✅（会自我修正）**|**具备闭环决策执行能力**|

> [!note] 学术界 4 张身份证
> 
>   
> 
> 1. **自主性（Autonomy）**：自己做决定。
>     
>       
>     
> 2. **反应性（Reactivity）**：动态感知环境。
>     
>       
>     
> 3. **主动性（Proactiveness）**：目标导向的主动行动。
>     
>       
>     
> 4. **社会性（Social Ability）**：与其他 Agent/人类协同。
>     
>       
>

## 🔄 第 3 站：核心循环、工具调用与协议标准

### 1. 核心循环（Agent Loop）

$$Thought \longrightarrow Action \longrightarrow Observation \longrightarrow (Next\ Thought...)$$

  

- **变迁墙效应**：每轮的 `Observation`（真实反馈）会被回灌到上下文“墙”上，下一轮思考能看到完整历史，而非重新单次开始。
    
      
    

### 2. Function Calling 的拓扑与工程底线

- **四大调用拓扑**：
    
      
    - **并行**：各参数/任务无依赖，并发提速。
        
          
        
    - **链式**：有前后数据依赖，排队执行。
        
          
        
    - **条件**：根据上一步工具返回值动态分支。
        
          
        
    - **嵌套**：工具内部封装调用其他底层工具。
        
          
        
- **工程底线**：模型只决定“调什么”和“传什么参数”，真正发起网络请求/执行代码的是你的宿主系统！
    
      
    

### 3. 工具 Schema 的黄金四原则

1. **命名**：动宾结构（如 `get_order_detail`），清楚明确。
    
      
    
2. **场景限制**：写清适用的业务边界和禁止调用的条件。
    
      
    
3. **参数类型**：严格限制，标明枚举范围和必填项。
    
      
    
4. **职责单一**：一个工具只专心做一件事。
    
      
    
5. **返回值设计**：必须返回**结构化 JSON**（严禁随意返回大段自然语言），且包含**机器可读的明确错误码与描述**，方便模型自我修复。
    
      
    

### 4. 协议标准：MCP vs A2A

代码段

```
flowchart TD
    subgraph 生态标准化
        A2A["A2A 协议 (Agent-to-Agent)<br/>👉 解决横向：同事间握手、状态同步、任务委派"]
        MCP["MCP 协议 (Model Context Protocol)<br/>👉 解决纵向：USB-C 式标准化向下连工具/数据源"]
    end
    
    A2A -.-> AGENT["AI Agent"]
    AGENT --> MCP
    MCP --> TOOLS["Tools / APIs / Resources"]
```

- **MCP vs Function Calling**：FC 是模型底层的能力，MCP 是生态级的标准接口规范，**FC 跑在 MCP 的标准通道上**。
    
      
    
- **框架选型速查**：
    
      
    - `LangChain`：工具箱，适合简单对话链。
        
          
        
    - `LangGraph`：状态机，核心优势在**条件边、图循环、断点持久化（Checkpointer，支持时间旅行调试与故障续跑）**。
        
          
        
    - `AutoGen`：学术对话派；`CrewAI`：拟人角色派。
        
          
        

## 🧠 第 4 站：推理范式三巨头与决策树

代码段

```
flowchart TD
    Q1{"任务步骤能否提前完整预判？"}
    Q1 -- "能（全局性好、成本可控）" --> PE["Plan & Execute (规划与执行)"]
    Q1 -- "不能（需摸石头过河、边查边定）" --> RE["ReAct (边想边做边修正)"]
    
    PE --> Q2{"任务执行失败的代价大不大？"}
    RE --> Q2
    
    Q2 -- "代价大（高可靠要求）" --> REF["叠加 Reflection (自审反思/错题本)"]
    Q2 -- "简单轻量任务" --> DIRECT["直接单步执行 (杜绝滥用复杂规划)"]
```

|**范式**|**运转逻辑**|**优缺点**|**工业界防线/配套 MD**|
|---|---|---|---|
|**ReAct**|走一步看一步，思考 $\to$ 动作 $\to$ 观察事实|灵活，但易**局部贪心**走偏|**步数上限闸门 + 循环死锁检测 + 超时熔断**|
|**Plan & Execute**|强模型做全局规划，轻模型具体执行|全局观好、成本更低|**动态重规划**（偏离预定路线时重新修正后半段）|
|**Reflection**|产出结果后过自审，带批注与错题本重跑|提升准确率，但每次多 1~3 次模型调用|**设置反思上限计数器**（防止无限反思无限烧 Token）|

> [!warning] 辨析点
> 
>   
> 
> - **ReAct vs CoT**：CoT 仅在内部思考，没有外部世界真实观察；ReAct 引入外部反馈，用事实修正下一步。
>     
>       
>     
> - **Reflection vs Retry**：Retry 是原样再试一遍；Reflection 是**完成错误归因后改变策略再试**。
>     
>       
>     

## 💾 第 5 站：记忆分层与上下文工程

### 1. 记忆金字塔架构

- **工作记忆（Scratchpad）**：当前轮推理的**草稿纸**，临时放置当前步骤的中间思考。
    
      
    
- **短期记忆**：本次会话上下文，使用 **Redis + TTL**，高频读写、生命周期短。
    
      
    
- **长期记忆**：跨会话资产，**语义向量存 PGvector，强结构化属性（画像、订单号）老老实实存关系型数据库（MySQL/PG）**，且需要攒轮次做后台异步提炼，避免垃圾污染。
    
      
    

### 2. 上下文工程防线（解决上下文腐烂/Lost in the Middle）

- **压缩策略**：长工具返回改为语义摘要。
    
      
    
- **内容外置（卸载）**：大体积返回存入外部文件，Prompt 仅保留路径引用。
    
      
    
- **窗口隔离**：多 Agent 之间各用独立小上下文，只传必要信息。
    
      
    
- **黄金余量规则**：**永远预留 30% 以上的上下文 Token 空间**应对未知的工具回包。
    
      
    

## 🐝 第 6 站：多智能体（Multi-Agent）与真实代价

### 1. 组织模式与通信

- **编排模式**：
    
      
    - **管道串行**：流水线，易被最慢木桶拖死。
        
          
        
    - **中控编排**：协调者分派，中心容易成瓶颈。
        
          
        
    - **同级辩论**：投票纠偏，极度烧 Token。
        
          
        
- **通信模式**：广播式、管道式、**黑板模式（Blackboard，共享状态读写，典型如 LangGraph State）**。
    
      
    

### 2. 生产落地警告

> [!danger] 多智能体的隐形成本
> 
>   
> 
> 1. **Token 消耗可达单 Agent 的 15 倍**。
>     
>       
>     
> 2. **误差级联放大**：A 节点的小偏差，传到 D 节点就变成灾难级事故。
>     
>       
>     
> 3. **严格顺序推理场景下，多 Agent 表现反而下降 39%~70%**。
>     
>       
>     
> 4. **工程原则**：优先单 Agent 跑通业务，确有“上下文隔离、强专业化分工”诉求再考虑拆分。
>     
>       
>     

## 🔍 第 7 站：Agentic RAG（从死板检索到自主探索）

代码段

```
flowchart TD
    subgraph 传统 RAG [一问一答，失忆检索]
        Q1[用户提问] --> R1[固定检索] --> G1[生成结果]
    end

    subgraph Agentic RAG [将检索作为循环工具]
        Q2[复杂多跳问题] --> LOOP{"自主判断是否检索？"}
        LOOP -- 需查新信息 --> TOOL1[改写 Query / 选路由知识库]
        TOOL1 --> RET[执行混合检索+重排]
        RET --> EVAL{"信息够不够？"}
        EVAL -- 缺失 --> TOOL2[切换数据源 / 换关键词继续查]
        TOOL2 --> RET
        EVAL -- 足够 --> ANS[综合生成输出]
    end
```

- **核心硬参数推荐**：
    
      
    - **分块（Chunking）**：200 ~ 500 Tokens，10% ~ 20% 重叠率，按语义边界切分。
        
          
        
    - **混合召回**：Dense Vector（语义）+ BM25（精确专有名词）。
        
          
        
    - **重排（Rerank）**：Cross-Encoder 重排序（提升 20%~30% 相关度）。
        
          
        

## 🛡️ 第 8 站：生产化、安全防护与面试实战套路

### 1. 线上翻车四层防线（字节真题）

代码段

```
graph TD
    A["调用层: 网络抖动/超时"] -->|"治理"| A1["重试 + 熔断 + 服务降级"]
    B["推理层: 工具调用报错/无数据"] -->|"治理"| B1["切换备用工具 / 返回默认值 / 优雅提示"]
    C["模型层: 幻觉 / Schema 解析失败"] -->|"治理"| C1["入参强校验 + 错误回灌自我修正 + 降级备用模型"]
    D["消费层: 下游业务系统异常"] -->|"治理"| D1["适配层容错 + 报警系统 + 转人工兜底"]
```

### 2. 安全防护 12 字真经

> **权限最小、输入消毒、输出审计**
> 
>   
> 
>   

- **防提示词注入（Prompt Injection）**：模型在底层机制上分不清指令和数据。
    
      
    
- **安全沙箱**：高危工具（如退款、删库）必须配**独立 Guardrail 审计层 + 人工审批卡点（Human-in-the-loop）**。
    
      
    

### 3. 系统设计与项目讲述通用框架

- **系统设计 6 步法**：需求澄清 $\to$ 能力拆解 $\to$ 画数据流与状态机 $\to$ 讲模块时序 $\to$ **说容量、降级与异常分支（拉开差距的关键点）** $\to$ 成本与效果折中。
    
      
    
- **项目介绍 STAR+ 高手四段论**：
    
      
    1. **冲突（Constraint）**：资源受限、延迟限制等硬约束。
        
          
        
    2. **决策（Trade-off）**：为什么先选该方案、放弃了什么。
        
          
        
    3. **量化（Metrics）**：任务完成率提升、P95 延迟（而非仅看平均数）、单次调用成本。
        
          
        
    4. **复盘（Retrospective）**：“如果再重做一次，我会怎么优化关键卡点”。
