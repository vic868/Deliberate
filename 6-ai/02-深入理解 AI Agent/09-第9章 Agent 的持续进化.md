## 核心知识点

### 9.1 能力悖论与一个关键区分（p264–265）

> Agent 可以零样本解决从未见过的复杂任务，却可能在处理了一万次相似任务之后，**第二天仍然犯下第一天的错误**。

原因：部署后的模型不会因为一次推理自动改变参数；第 2 章的上下文学习只适应当前任务；把对话存进记忆也不等于学会新行为——原始轨迹里混着有效策略、偶然成功、错误归因和不可信输入。

> **「保存经历不等于从经历中学习」**：把一百条轨迹放进长上下文或向量库，能帮模型找回某个案例，却不会自动完成跨案例比较（哪些步骤在成功轨迹中反复出现、哪些做法只在旧版接口有效、某次成功来自正确策略还是环境偶然）。学习发生在系统主动完成「**评价、对照、归纳、验证**」之后，而不是日志写入磁盘的那一刻。

与第 3 章的分工：第 3 章沉淀「**用户与世界是什么样的**」，本章沉淀「**在什么条件下应该怎样行动**」；前者让 Agent 记得更多，后者让它做得更好。

### 9.2 四种更新载体（p266–274）

判定标准只有一条：**目标能力能否被外部符号较完整地表达**。

| 载体 | 适合什么 | 形态 |
|---|---|---|
| **① 知识** | 反复出现的经验事实 | 可检索的经验知识库（与第 3 章共享存储/索引/检索，但来源与验证目标不同） |
| **② 指令** | **能用语言清楚描述**的策略错误 | 系统 Prompt（所有任务生效）/ Skill（匹配领域或工具时按需加载） |
| **③ 程序** | 稳定、重复、**可验证**的操作 | 编译成工作流、工具或 Harness 代码，让一次探索变成可重复执行的程序 |
| **④ 参数** | 难压缩成规则的高维能力 | 医疗影像理解、语音韵律、消除「AI 味」、长程规划 → 必须后训练（第 8 章） |

9.2.3 特别指出：不是一般的代码生成，而是 **Agent 根据自己的轨迹修改未来版本的自己**。9.2.4 用「弯引号的作用域判断」说明中间地带怎么切：文档语法边界交给程序解析、语境与例外交给 Skill、跨任务的识别习惯才适合写入参数。

**9.2.5 一条正交的轴**：优化的究竟是某份**产物的内容**，还是产生、管理与验证这些产物的**方法**？搜索尺度逐层扩大为：

```
单条规则或记忆 → 结构化上下文 → 工作流 → Harness 代码 → 产生更新提案的优化器代码
```

### 9.3 双循环与安全边界（p275–278）

```
在线执行循环   完成任务 + 追加不可变证据（不直接改写正式 Agent）
      │  版本化的经验库 / 评估集
离线进化循环   聚合轨迹 → 诊断根因 → 生成更新提案 → 验证门槛 → 发布新版本
```

- **9.3.1 可验证闭环的边界**：Coding、工具调用、业务状态变更最容易成立（测试 / 环境状态 / 确定性规则能快速反馈）。开放式科研、战略规划、复杂产品设计则评价信号慢、正确答案不唯一——此时 Harness 可能把流程执行得非常完整，却只是**稳定地产出「像成果的东西」**。「完成」不等于「进步」。
- **9.3.2 安全边界**：网页/邮件/工具输出里的**提示注入若被总结成经验，会跨会话反复生效**；自动搜索到的恶意软件包被封装成工具，影响从一次沙盒扩散到所有后续任务；**有缺陷的验证器会持续批准看似进步、实际退化的版本**。因此除了验证「是否更强」，还必须限制「谁能改什么、改哪里」——**可信根不能被 Agent 自己修改**（思考题 4）。
- **9.3.3 睡眠学习**：对离线整合的认知类比，不要求真在夜间跑。在线只采集不可变证据，后台在空闲期或满足门控时批量比较新旧结论、合并重复、解决冲突、提出提案并跑回归。把**采集与整理分开**，可防止一次偶发成功、网络故障或恶意输入立刻改写长期能力。

## 结论与金句

> 「今天的模型还无法自行完成可靠的持续学习。推理时的上下文适应不会自动持久化，未经验证的在线参数更新又会放大噪声、攻击和能力漂移。因此，现阶段更可行的路径，是**在模型外围建立可验证的学习系统**。」（p278）

后记进一步点明：第 9 章尤其依赖前文全部基础——没有轨迹和知识系统，经验无处保存；没有代码能力，Agent 无法修改工具与 Harness；没有评估，系统无法判断一次修改是进步还是退化。

## 思考题（原题精选，PDF p279）

1. ★★ 一条经验由三次成功 + 一次失败支持，失败发生在**较新的 API 版本**上——如何判断是经验被推翻，还是适用条件变了？
2. ★★ 客服 Agent 满意度上升但规则违规率也上升，为什么不能把满意度作为单一学习信号？如何设计**护栏指标**？
3. ★★★ 同一个「虚假承诺」问题可用 Prompt、Harness 检查或参数训练缓解，依据哪些证据选择修改位置？
4. ★★★ Agent 能改工具和验证器，却不应改批准自身更新的**可信根**——如何划分权限与代码边界？
5. ★★ 经验知识库膨胀后，检索错误与知识冲突会抵消学习收益，如何设计版本、时效与淘汰机制？
