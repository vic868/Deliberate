# 第 3 章 用户记忆和知识库

## 核心知识点

### 3.1 两个尺度，一套底座（p81）

| | 用户记忆 | 知识库 |
|---|---|---|
| 尺度 | 个体：偏好、习惯、需求 | 群体：法规、流程、专业文档 |
| 目标 | 「懂你的助手」 | 「领域专家」 |
| 共性 | 向量检索、知识压缩、冲突/过期/检索不准 | 同左 |

两条线索最终汇合于**双层记忆架构**：`Advanced JSON Cards` 常驻概览 + 上下文感知检索按需取细节。关键区别：用户记忆**不保存每句对话**，而是用额外的 LLM 调用提取、压缩并审查对未来有用的事实；这与只在当前窗口生效的上下文学习不同。

设计拆成三个独立维度：**放哪里（层次）· 怎么存（格式）· 存什么（内容类型）**。

- **层次**（3.1.2）：轨迹（Trajectory，一次运行的完整历史）→ 工作记忆（上下文窗口）→ 长期记忆。
- **四种存储格式**（3.1.3）：粒度与结构复杂度递进，小结里点名 `Simple Notes` → `JSON Cards` → `Advanced JSON Cards` → 可执行状态。
- **进阶形态**（3.1.4）：`User as Code` 把用户状态改成**带类型的可执行对象**，规则写成普通函数，让「表示」与「推理」使用同一种可验证介质；借鉴「预写日志 + 检查点」，会话结束先追加只增日志，再定期从完整日志重建状态。书末脚注还提到 `User as Engram`（arXiv:2606.19172，2026）——不训练每用户 LoRA，而是把用户事实插入预训练模型的哈希 N-gram 槽位、无需梯度更新。
- **认知科学基础**（3.1.5）：工作记忆对应上下文窗口；长期记忆再分不同类型。
- **框架案例**（3.1.6）：Mem0「从写入时消歧到检索时推理」的演进，对照 Memobase。
- **压缩整理**（3.1.7）：重要性评分综合**访问频率、时间衰减、情感强度**等因素，做多层次压缩，避免记忆爆炸。
- **隐私**（3.1.8）：日志脱敏，实验 3-3 用 Ollama 跑本地 Qwen3-0.6B 小模型，在 CPU / 消费级设备上即可运行。

### 3.2 RAG 主流水线（p89–95）

```
分块 Chunking → 稠密嵌入 / 稀疏嵌入 → 融合 → 重排序 Rerank → 生成
```

- **为什么要分块**（3.2.1）：① 嵌入模型有输入长度限制；② 整篇文档压成一个向量会让多个主题混在一起，向量无法精确表达任何一个。这是查询时「检索 → 增强 → 生成」之前的**离线预处理**。
- **稠密嵌入**（3.2.2）：把词句映射成高维向量，语义相近的点也相近；擅长语义，可能漏掉精确关键词。
- **稀疏嵌入**（3.2.3）：根植于传统 IR 的词袋模型，极高维、绝大多数为零，只做精确关键词匹配；擅长 `HTTP-403` 这类精确串，读不懂同义词（搜 `kitty` 找不到只写 `cat` 的文档）。
- **混合检索**（3.2.4）：两个引擎都跑再合并，**难点是把分布迥异的两组得分整合成有意义的排序**。验收用 `recall@k` 等指标。

### 3.3 超越扁平文本（p96–108）

扁平切块会丢掉知识固有的层次与跨文档关联。四条改进路线：

| 路线 | 做法 | 出处 |
|---|---|---|
| 结构化索引 | 索引前先用 LLM 归纳建关联：**RAPTOR** 树状层次摘要 / **Graph RAG** 实体关系图 | p97 |
| 文件系统范式 | 字节 OpenViking：把记忆、资源、技能全部映射成虚拟文件系统目录与文件，每条有唯一 `viking://` URI | p100 |
| 更新机制 | **事件触发的增量更新**（吸收新证据）+ **周期触发的全量整理**（回原始数据去重、合并、重建索引） | p101 |
| 检索控制 | **智能体化 RAG**：把「查询→检索→注入→生成」的被动单向流，改成 Agent 自主决定何时检索、检索什么；另有上下文感知检索（给分块附原始文档上下文） | p102–105 |

写入纪律（本章小结）：**不能跳过来源、时间、冲突和隐私检查**；待验证的 diff 通过独立审核后才发布。

## 结论与金句

> 「用户记忆遵循『读取相关记忆 → 后台提取候选 → 来源与策略核验 → 更新』的生命周期。」（p109）

> 「就全书的结构而言，本章建的是第一章发现循环中的**提案段**：把一条证据变成一次最小、可审查、可回滚的修改，而不负责判断系统整体是否变好。」（p109）

这句是全书结构的关键伏笔：第 3 章只管「提出修改」，**判断是否真的变好**是第 7 章评估、第 9 章持续进化的职责。

## 思考题（原题精选，PDF p110）

1. ★★ 同一用户在不同会话给出矛盾信息（两次不同住址），记忆系统如何处理冲突？
2. ★★ 上下文感知检索给分块附原始文档上下文，若原文本身混乱或矛盾会放大错误——如何在检索阶段引入「信息质量」信号？
3. ★ Rich Sutton「苦涩的教训」认为通用方法终将胜过手工特征——本章的分块/索引/检索管道是否本身就是手工设计？模型够强时会被「全量输入」替代吗？
4. ★ RAPTOR 与 Graph RAG 分别擅长什么类型的查询？
5. ★★★ 为 Markdown 用户记忆库设计增量更新 + 定期整理流程；若 Reviewer 与 Proposer 用同一模型且只看 Proposer 挑的片段，仍可能合入哪些错误？从**模型独立性、证据覆盖、工具权限**三方面改进。
