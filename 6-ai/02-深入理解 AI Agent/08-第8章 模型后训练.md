### 8.1 四阶段地图（p225–227）

> [!tip] 💡 大白话
> 先补常识（Mid-training）、再教规矩（SFT）、最后用奖惩练策略（RL）；前七章都在改装备，只有这一章真的动大脑。

| 阶段 | 做什么 | 类比 |
|---|---|---|
| **预训练** | 海量互联网文本上做「预测下一个词」（NTP），学语言规律、世界知识、基本推理 | 读完图书馆所有书，博学但不会好好回答；最贵（动辄数千万美元） |
| **Mid-training** | 从已有基础模型出发，在目标语言、领域文档、代码、长上下文或能力数据上**继续做语言建模** | 不是重建地基，而是补通用预训练没覆盖的缺口 |
| **SFT** | 用「用户提问 → 理想回答」的输入-输出对做监督微调，稳定格式与协议 | 教它「如何回答」 |
| **RL** | 用奖励评估模型自己生成的回答，重新分配概率、探索策略 | 教它「怎样做得更好」 |

两个必须打通的认知：

- **SFT 在数学上和预训练是同一个任务**——都是预测下一个词、最小化同一个损失；差别主要在**数据**（精心准备、格式统一）与目标范围。很多初学者以为 SFT 是全新方法，其实不是。
- **RL 需要两个前提**：① 输出能被验证；② 当前策略**偶尔能探索到有价值的行为**。若任务要求输出 JSON / 工具调用而模型吐出不可解析文本，奖励函数连成败都判断不了，此时应先做 SFT 稳格式。

> 8.1.5 对照实验结论「**SFT 记忆、RL 泛化**」只是受控实验里观察到的倾向，**不是不受数据、模型、奖励与环境影响的普遍规律**（本章小结特别澄清）。

### 8.7 三条选择规则（p243 / p262）

> [!tip] 💡 大白话
> 输出能不能判对错、模型偶尔能不能蒙对，决定该用哪种训练；连 JSON 都吐不整齐时，先回去把格式教稳。

| 现象 | 该做什么 |
|---|---|
| 合理采样下 `pass@k` 仍接近零 | **Mid-training** 补知识与能力（先按主题/语言/文档类型/上下文长度切分评估，定位低分来自哪类底座缺口） |
| 模型偶尔会做，但输出不可解析 | **SFT** 稳定格式 |
| 当前策略能产生**可评分且有奖励差异**的轨迹 | **RL** 才高效 |

第 7 章的问题案例可直接转成训练数据：以「Coding Agent 过早结束」为例，截出「准备宣称完成」的轨迹前缀，把过早宣称作为 `rejected`、把「先跑测试、逐条核对验收条件再下结论」作为 `chosen`——**适合做 DPO 或决策边界示范，而不是直接当作正确的 SFT 轨迹**。8.14 还有「中文引号」「编辑文件经常失败」两个案例。

### 8.9 GRPO 与 On-Policy（p247–248）

> [!tip] 💡 大白话
> 同一道题让模型做 16 遍，比出谁好谁差再调参，不用另请裁判；但生成答案的那个策略，必须就是正在练的那个。

- **GRPO**（Group Relative Policy Optimization，DeepSeek 提出）用「16 次 rollout → 一次参数更新」的 SWE-bench 修复例子讲清组内相对优势如何替代价值网络。
- **Online ≠ On-policy**（8.9.1）：Online 只表示数据在训练中不断由交互产生；**On-policy 要求生成 rollout 的行为策略与当前待优化策略相同或足够接近**。异步集群即使持续在线生成，只要 rollout worker 落后几个 checkpoint，数据在统计意义上就已陈旧、带有 off-policy 性质。
- 训练—推理数值失配会破坏这一前提，因此 **sampler / trainer 一致性应与奖励曲线同等重要**。

### 8.10–8.13 环境、奖励与蒸馏

> [!tip] 💡 大白话
> 没有真实环境就让模型演，可它演得不像，练出来的上限也卡在那儿；奖励又晚又稀，还得想清楚该怪哪一步。

- **RL 环境**（8.10）：造不出真实环境时，可让模型扮演环境（合成工具返回值、仿真环境动态），但**模拟器的偏差就是训练的天花板**；环境、任务分布与评估要隔离。
- **多轮信用分配**（8.11）：把环境带进 Agent 的工具调用让单轮变多轮，最终成功/失败信号出现得又晚又稀疏，归因比单轮严重得多。
- **奖励设计**（8.12）三问：奖励来自哪里（规则 / 人类偏好 / 模型评判）、何时给（结果 vs 过程）、表达多少信息（标量 / 向量 / 生成式诊断）；「结果正确还不够」引出**路径约束与 RLVP**（把被浪费的环境反馈变成可学习信号）。
- **蒸馏**（8.13）：教师模型只需「**明显高于学生**」，不必全球第一；200B 及以下规模用开源 SOTA 当教师已够用。在轨蒸馏让一次 rollout 产生**逐 token 的密集监督**（而非只有终点标量），没有更强教师时用 On-Policy 自蒸馏。

## 结论与金句

> [!quote] 原文金句
> 「**数据和环境比算法更重要**：Mid-training 语料决定底座补到了哪里，SFT 示范决定协议是否稳定，环境和奖励决定 RL 能探索并强化什么。很多场景下，只要底座和示范数据到位，甚至不需要做 RL。」（p262）

> [!quote] 原文金句
> 「当前 RL 的主要瓶颈是**样本效率与分布一致性**。」（p262）

本章回答「怎样通过更新模型参数实现持续进化」，紧接一句收口：**参数只是第 9 章四种自我进化载体之一**（知识 / 指令 / 程序 / 参数）。

## 思考题（原题精选，PDF p262）

> [!question] 自测 · 先自己答，再回 `_原文/` 核对原题

1. ★★ **灾难性遗忘**：针对特定任务的微调破坏了通用工具调用能力。LoRA 冻结基座、风险更低但不免疫，还有哪些缓解策略？
2. ★★ 后训练把能力固化进权重（「肌肉记忆」），上下文学习把知识放在推理输入里——用什么标准决定某项能力走哪条路径？
3. ★★ 蒸馏 Chat / Reasoning / Agentic 三类模型，难点有何不同？（提示：要蒸馏的是输出风格、完整思考轨迹，还是与环境交互的**决策策略**；轨迹里哪些 token 该学、哪些是环境返回的不该学；成败信号有多晚多稀疏。）
4. ★★★ 多轮 Agent 交互中的信用分配比单轮更严重，一个最终成功可能来自早期某步——如何归因？
