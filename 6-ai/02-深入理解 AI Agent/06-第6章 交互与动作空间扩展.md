## 核心知识点

### 6.1 两根轴（p162）

| | 观察空间的扩展 | 动作空间的扩展 |
|---|---|---|
| **内容**（第 2–5 章） | 上下文工程、记忆与知识库 | 工具、代码生成 |
| **模态**（本章） | 语音、屏幕、物理传感器 | 说话、点击、关节运动 |
| **时机**（本章） | 世界主动推送、连续流 | 跨回合、可打断、可抢占 |

> 关键判断：**回合制是模型与接口的一种交互约定，不是环境的性质**。真实环境不会等模型作出反应——邮件在它思考时到达，用户说到一半会改口。

### 6.2 异步与事件驱动（p163–173）

第 1 章五类工具里剩下的**事件触发 / 用户沟通**两类在这里展开（模态仍是文本，变的只有时机）。

- **骨架是事件循环（event loop）**：长期运行的循环每轮从输入队列取若干事件、追加到轨迹、调用一次 LLM；一个实例可能同时面对用户新消息、工具结果、定时器到期、其他 Agent 协作请求。
- **Open Claw** 通过 Gateway 控制平面接收多渠道消息并路由，内置 Hooks（生命周期事件，类似 GitHub Actions）、Cron（定时调度）等机制。
- **虚拟身份与隔离执行环境**（6.2.5）：让 Agent 直接管理用户个人账号看似便捷，但一旦出错或被攻破，用户全部数字身份暴露；更稳妥是给 Agent 一套独立的邮箱 / 号码等虚拟身份。
- **两条技术路线**：① 模型/接口不支持原生异步时，在**同步格式中表达异步语义**（工具未返回时被打断的兼容方案）；② **模型原生异步**——GPT-6 Astra 支持 `Async tool calling` 与 `Mid-turn steering`（回合中途引导）。
- **6.2.9 从「能收到消息」到「可靠处理任务」**，至少检查三件事：**结果归属与未完成状态**（延迟结果归入正确任务、结果缺席时不编造）、**任务恢复与动作控制**（处理新要求后继续原任务、区分改计划与停止）、**多条更新的综合使用**（同时遵守预算与人数等约束）。

### 6.3 语音三范式（p173–179）

说话速度约为打字的四倍且不占双手视线，天然适合持续工作、随时可被打断的回路。

| 范式 | 结构 | 优势 / 限制 |
|---|---|---|
| **级联 Cascading** | `VAD → ASR → LLM → TTS` | 模块化、每级可独立优化；每级都增加延迟，转文本时丢失情绪与环境声 |
| **端到端 Omni** | 同一模型直接听音频、生成并输出语音 | 保留非文字信息、延迟低；训练成本高，仍分「用户说 / 模型说」两个时段 |
| **全双工** | 持续听、持续说，不预设轮次 | 支持重叠说话与打断（Kyutai Moshi 2024 为先声）；控制最复杂 |

- **认知时序**（6.3.5）：「交互表现」与「智能上限」是两个维度——**前台快模型维持对话节奏，后台慢模型负责深度思考**；三种方案是设计取舍，不是线性迭代。
- **更像人的语音合成**（6.3.6）：让主 LLM 在文本之外输出 `THINKING`、`EMO:happy`、`SPEED:0.8x` 等控制标记，由 TTS 映射为停顿、韵律、语速、笑声。传统 TTS 过于流畅、零停顿，反而暴露机器身份。

### 6.4–6.5 屏幕与物理世界

- **Computer Use**：动作空间设计、视觉定位（Grounding）——`SoM（Set-of-Mark）` / DOM 元素索引把开放坐标预测转成**封闭 ID 选择**，但非标准控件或动态元素会标注不全；另有连续视觉理解、动作后的状态确认、世界模型、移动端生态壁垒。
- **机器人（XLeRobot 整理桌面）**：硬件与算法分工 → 控制基本结构 → 长程规划与任务分解 → **VLA（视觉-语言-动作）** → VLA 局限 → 世界模型 → 从仿真到真实机器人。动作分块（一次生成多个连续动作）在**平滑性与反应速度**之间取舍。

## 结论与金句

> 「四节共享同一条控制骨架……而最终是否完成，**仍必须由新的观察来判定**。」（p189）

本章按第 1 章 1.2.6 的说明**不属于 Harness 五要素**：五要素管「怎么组织已有的上下文与工具」，第 6 章扩展的是观察 / 动作空间本身的**模态与时机**。

## 思考题（原题精选，PDF p190）

1. ★★ 事件队列优先级判断本身需要语义理解（新消息是否更紧急），由规则引擎还是另一次 LLM 调用来做？各有什么代价？
2. ★★ 队列积压 20 个事件（10 工具结果 + 5 用户消息 + 5 系统提醒），如何组织顺序与格式让模型不遗漏？模型倾向于只关注最后一个事件。
3. ★★★ 虚拟身份（第三方行动）vs 直接以用户本人身份操作账号，各适合什么场景？
4. ★★ 端到端语音模型出错时比串行管道难调试，如何设计其**可观测性**系统？
5. ★★ SoM / DOM 标注不全时，应回退到坐标预测吗？
