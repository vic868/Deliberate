# 2-RAG

> [!abstract] 一句话概述
> 如果说 LM 是 Agent 聪慧的大脑，那么它天生就有一个致命的弱点：遗忘和幻觉。
LM 的知识被局限于其训练数据截止日期，无法感知现实世界的最新动态。同时，它在回答其知识边界以外的问题时，有时会一本正经地胡说八道，产生所谓的“幻觉”。
为了克服这个根本性的缺陷，RAG 架构应运而生，并迅速成为构建高可用性知识密集型 Agent 的主流范式。

> [!tip] RAG 核心架构
> 1. 用户提问：
> 2. 检索系统并不会立即将问题抛给 LM，而是将其发送给一个检索模块。该检索模块会根据问题的语义，从庞大的外部知识库、公司内部文档、最新的网络资讯、专业的学术论文中，精炼地检索出与问题相关的信息片段。
> 3. 生成：系统将用户的原始问题与从知识库中检索到的相关片段，共同整合成一个更为丰富的提示，然后才将其交给 LM。这时的 LM 如同拿了一份详细的参考资料，它的任务不再是凭空解答，而是在这些可靠的材料的基础上进行总结、提炼和组织，最终生成一个有据可依的答案。

## 🗂️ 知识库的构建与检索系统设计

### 1.  文档分块与向量化
处理大规模文档时，需要先进行分块（chunk），再利用嵌入模型（如 OpenAI embedding、sentence transformers）将每个分块转化为向量，便于后续的相似度检索。
高质量的知识库与高效检索系统是 RAG 的系统核心。开发者需关注文档分块、向量化、数据化选型等细节，确保检索的准确性与性能。


### 2. Rag 系统的评估与优化（从”能用“到”好用“的必经之路）
构建一个 RAG 系统如同装配一台精密的仪器，其各个部件——文档处理、向量嵌入、检索策略、语言模型的性能与协作方式，共同决定了最终输出的质量。

####  1️⃣ 精准度量定义 RAG 系统的核心评估维度。
 
 
 对 RAG 系统的评估必须是多维度的，因此它本质上是一个级联系统（cascading system），上游的微小偏差可能会在下游被放大。


>[!tip] 核心维度 
>1. 检索质量（retrieval quality）。这是根基
>	1. 上下文精确率。Context precision.只检索出的信息片段中，真正与用户问题相关的所占比例。这个指标衡量了检索结果的信噪比，精确率低意味着向 LLM 提供了大量无关的噪声。
>	2. 上下文召回率（Context Recall），指所有与问题相关的正确信息中被成功检索出来的比例，这个指标衡量了检索查全率。召回率低意味着关键信息遗漏，LLM 将因缺少素材而无法作答。
>2. 生成质量（Generation Quality），这是 RAG 的最终呈现。
>	1. 忠实度 faithfulness。衡量生成的答案是否严格基于所提供信息的上下文。这是衡量模型是否产生幻觉的关键指标，忠实度高意味着答案的每一个论点都能在检索到的原文中找到依据。
>	2. 答案相关性（Answer Relevance）：判断生成的答案是否直接清晰地回答了用户的原始问题，有时即使答案内容全部忠实于原文，也可能因为组织不当或者偏离重点而没有满足用户需求。
>3. 系统性能 system performance.这是衡量系统工程效率和经济可行性的重要维度。
>	1. 端到端延迟（End to End Latency），从用户提问到获得完整答案的总耗时，是影响用户体验最直观的指标。
>	2. 成本（cost）：每次查询所消耗的计算资源与 API 调用费用。


### 2️⃣自动化评估，建立可持续的质量监控流水线。
依赖纯人工评测虽然精确，但成本高昂且难以规模化，因此构建一个自动化测试与评估流水线至关重要。其核心是创建一个高质量的黄金测试集（golden test set），其中每一条数据都包含一个典型的问题，及其期望的答案或者是关键信息点。



###3️⃣优化策略： 系统性的提升 Agent 的问答能力。
评估结果不尽如人意时，我们将像一位经验丰富的医生一样对系统进行诊断和治疗。优化的手段是多层次的，可以针对系统的不同环节进行。
1> 优化检索阶段，提升上下文质量。
	1.文档分块策略（chunking）将文本分割的力度（chunking size）和重叠量（chunking overlap）。过大的块可能包含太多无关信息，过小的块则可能割裂语义的完整性。找到合适数据特性的分块策略是优化的第一步。
	2.嵌入模型 embedding model。更换一个更强大的嵌入模型，模型的表征能力直接决定了语义检索的上限。针对特定的领域，甚至可以考虑采用微调（fine-tuning）嵌入模型。
	3.高级检索技术:引入更复杂的检索策略。
	4.混合搜索（Hybrid Search）结合传统的关键词搜索（如 BM25）与向量的语义搜索，取长补短。
	5.重排序 reranking 在初步检索召回出一批候选文档后，使用一个更精密的交叉编码器 cross encoder 模型对这些文档进行二次排序，从而将最相关的文档排在最前面
2>优化生成阶段，提升答案质量。
	1.提示工程:精心设计输入给 LLM 的最终提示。例如，可以明确提示模型：“请仅根据提示的上下文回答问题”，以增强其忠实度。
	 2.更换或微调生成模型：选用一个在特定任务（如总结、问答）上表现更优的 LLM；或者在高质量的 问题-上下文-答案 数据中对现有模型进行微调。
RAG 系统的持续评估与优化是一个贯穿 Agent 全生命周期的动态过程，唯有将自动化测试与人工反馈深度结合，进行数据驱动的迭代，才能够最终打造出一个真正智能、可靠且值得信赖的 AI Agent。
